# 프로젝트 특성 카탈로그

> PM과 ARCH가 함께 쓰는 목록이다(레지스트리 `SK-TRAIT`). PM은 P0(접수)에서 특성마다 판정하고, 판정에 따라 이 파일의 항목을 P2~P7에 더한다. ARCH는 A0에서 판정을 검증하고, 판정에 따라 이 파일의 항목과 팩을 A1~A7에 더한다.
> 모든 프로젝트에 적용하는 **코어 항목은 각 스킬 본문**에 있다. 이 파일에는 특성별로 **더하는 항목만** 둔다.
> 특성을 추가할 때는 같은 형식으로 쓰고 TR 번호를 이어서 매긴다. 번호는 재사용하지 않는다.

## 판정 값

| 값 | 뜻 | 적용하는 항목 |
|---|---|---|
| `해당` | 이 특성이 범위에 있다 | 모든 항목 |
| `해당(대체)` | 요구는 있지만 `범위 제외` 제약 때문에 다른 동작(상태 변경·로그 등)으로 대신한다 | PM 관점, PM 산출물 중 REJ·AC만. ARCH 항목은 대체 동작 설계에 필요한 것만 |
| `해당 없음` | 범위에 없다 | 없음. 근거를 반드시 단다 |
| `불명` | 판단할 근거가 없다 | 질문으로 올린다. 확인 전에는 다음 단계로 넘기지 않는다 |

판정마다 근거(DOC-ID와 위치, C-ID, 사용자 답변, P1 이후에는 REQ-ID)와 범위 등급(Must / 하위 등급 이름 / Won't)을 단다.

## 항목 형식
- **판별 신호**: 요구사항·프로파일에서 이 특성을 알아보는 단서. 신호가 보인다고 곧 `해당`은 아니다. 판정은 근거로 한다.
- **PM 관점 (P2)**: P2 매트릭스 축 B에 더하는 행 (`관점 | 확인할 질문`)
- **PM 산출물**: P3~P7에 더할 것 (태스크 번호를 앞에 붙인다)
- **ARCH 결정 (A2)**: 결정 영역. 코어 ADR에 포함되는 것은 "코어 ADR-00x에 포함"으로 표시한다
- **ARCH 리스크 (A1)** / **ARCH 흐름 (A5)** / **ARCH 게이트·테스트 (A7)**
- **팩**: 특성별 상세 체크리스트·산출물 형식 파일(`.claude/skills/pm-agent/references/packs/<이름>.md`). 파일이 적혀 있으면 PM·ARCH가 이 특성의 항목을 다룰 때 함께 읽는다. "없음"이면 이 카탈로그의 항목만 쓴다.

### TR-01 계정·인증
- **판별 신호**: 회원, 로그인, 본인 데이터, 역할별 기능
- **PM 관점**: `계정·개인정보 | 가입 필수 항목, 비밀번호 규칙, 응답에 민감 정보가 나가지 않는가, 본인 데이터만 보는가` / `인증 수명 | 만료, 로그아웃·탈취 시 무효화, 동시 로그인 허용 여부, 무차별 대입`
- **PM 산출물**: P3 계정 도메인과 인증 관련 INV / P5 REJ(인증 없음, 만료·무효화된 인증, 권한 없음) / P6 NFR(무효화된 인증으로 요청 시 거부, 어떤 응답에도 비밀번호 해시 없음)
- **ARCH 결정**: 코어 ADR-002에 포함(인증·권한 세부)
- **ARCH 리스크**: 무효화된 인증 수단의 재사용, 무효화 기록을 저장한다면 그 저장소의 무한 증가, 타인 리소스 접근, 무차별 대입
- **ARCH 흐름**: 가입, 로그인, 인증 확인, 로그아웃(또는 무효화)
- **ARCH 게이트·테스트**: 무효화된 인증 거부, 응답 스키마의 민감 필드 부재
- **팩**: 없음

### TR-02 경쟁 자원
- **판별 신호**: 정원, 재고, 좌석, 한도, 선착순, 중복 신청 금지
- **PM 관점**: `경쟁 자원·동시성 | 자원 한도의 최소·최대, 동시에 요청하거나 요청과 취소가 겹칠 때 결과, 1인당 한도, 취소 후 재신청`
- **PM 산출물**: P3 한도 INV / P4 D-003에 자원 한도의 단위·1인당 한도 포함 / P5 REJ(자원 한도 초과) / P6 NFR(한도 N에 동시 요청 M건(M > N) 후 확정 수 = N, 초과 0)
- **ARCH 결정**: 동시성 제어 방식(잠금 / 조건부 갱신 / 유일 제약 등)과 연결 풀 값
- **ARCH 리스크**: 동시 요청 시 한도 초과·중복 확정, 교착
- **ARCH 흐름**: 확보(신청·차감), 해제(취소·반환), 같은 요청 두 번
- **ARCH 게이트·테스트**: 동시 요청 M건 후 한도 초과 0
- **팩**: 없음

### TR-03 실시간 상호작용
- **판별 신호**: 실시간, 화면 즉시 반영, 서버가 먼저 보내는 갱신, 채팅, 접속 상태, 지연 시간 수치
- **PM 관점**: `연결 수명주기 | 접속·끊김·재접속 유예 시간, 여러 탭·기기 동시 접속` / `전달 보장 | 이벤트 순서가 바뀌거나 누락·중복될 때 결과, 지연 허용치`
- **PM 산출물**: P3 연결·세션 상태 / P6 이벤트 AC("누가 어떤 이벤트를 몇 초 안에 받는다"), NFR(지연 p95, 동시 접속 수) / P7 연결 상태 표시
- **ARCH 결정**: 전송 방식(지속 연결 / 서버 전송 이벤트 / 주기 조회), 메시지 프로토콜(이벤트 종류, 공통 봉투, 순서·확인), 지속 연결의 인증 방법, 연결 상태 저장 위치와 여러 프로세스 간 전달, 하트비트·놓친 이벤트 재동기화
- **ARCH 리스크**: 여러 작업 프로세스에 연결이 흩어져 전달 누락, 끊긴 연결의 유령 상태, 무효화된 인증으로 열려 있는 연결, 메시지 폭주·과대 크기, HTTP 전용 미들웨어가 연결 요청을 거치지 않음
- **ARCH 흐름**: 연결 수립(인증 포함), 이벤트 발행·수신, 끊김·재접속
- **ARCH 게이트·테스트**: 연결 통합 테스트(수립·이벤트 수신·재접속), 무효화된 인증의 연결 거부
- **팩**: `.claude/skills/pm-agent/references/packs/realtime.md`

### TR-04 매칭·대기열
- **판별 신호**: 매칭, 대기열, 방·로비, 팀 구성, 자동 배정
- **PM 관점**: `매칭 정책 | 묶는 조건(인원·실력·지역 등), 대기 시간에 따른 조건 완화, 파티 단위 참가, 대기 취소·이탈` / `배정 공정성 | 대기 순서 보장, 한 사람이 동시에 두 곳에 배정되지 않는가`
- **PM 산출물**: P3 대기열·매치 상태 흐름, INV(1인 1활성 대기·매치) / P4 D-003에 매칭 정책 포함 / P6 NFR(매칭 대기 시간 p95)
- **ARCH 결정**: 매칭 실행 방식(요청 시 / 주기 실행 / 별도 작업자), 대기열 상태 저장 위치, 배정의 원자성 보장 방법(TR-02와 같은 ADR로 묶을 수 있다)
- **ARCH 리스크**: 이중 배정, 대기열에 남는 고아 항목, 매칭 실행이 멈춤
- **ARCH 흐름**: 대기 등록, 매칭 성사, 대기 취소, 매칭 후 이탈
- **ARCH 게이트·테스트**: 동시 대기 등록 후 이중 배정 0
- **팩**: `.claude/skills/pm-agent/references/packs/matchmaking.md`

### TR-05 시간 기반 규칙
- **판별 신호**: 타임아웃, 만료, 예약 시각, 마감 시간, "N초 안에"
- **PM 관점**: `시간 전이 | 시간이 지나면 바뀌는 상태, 전이 주체(시스템), 경계 시각의 처리`
- **PM 산출물**: P3 상태 흐름에 시간 전이 행(주체: 시스템) / P6 AC에 시간 조건
- **ARCH 결정**: 시간 전이 실행 방식(조회 시 판정 / 예약 실행), 현재 시각 주입 방법
- **ARCH 리스크**: 실행 지연으로 전이 누락, 현재 시각에 의존하는 테스트의 불안정
- **ARCH 흐름**: 시간 전이 처리
- **ARCH 게이트·테스트**: 고정 시각을 주입한 경계 시각 테스트
- **팩**: 없음

### TR-06 백그라운드 처리
- **판별 신호**: 응답 뒤에 하는 처리, 주기 작업, 일괄 처리
- **PM 관점**: `비동기 결과 | 사용자가 결과를 언제·어떻게 확인하는가, 실패하면 무엇을 남기는가`
- **PM 산출물**: P5 흐름에 비동기 단계 표시 / P6 AC(응답과 작업 결과를 따로 확인)
- **ARCH 결정**: 실행 방식(프레임워크 기본 기능 / 작업 큐 / 별도 프로세스), 재시도·실패 기록
- **ARCH 리스크**: 작업 유실, 중복 실행, 응답 트랜잭션과 작업의 불일치
- **ARCH 흐름**: 작업 등록·실행·실패
- **ARCH 게이트·테스트**: 작업 실패가 응답에 영향 없음
- **팩**: 없음

### TR-07 파일·대량 데이터
- **판별 신호**: 업로드, 다운로드, 내보내기(CSV 등), 대용량 목록
- **PM 관점**: `데이터 크기 | 최대 크기·건수, 형식, 진행 표시`
- **PM 산출물**: P6 NFR(최대 크기·건수, 처리 시간)
- **ARCH 결정**: 저장 위치, 스트리밍 여부, 크기 제한 위치
- **ARCH 리스크**: 메모리 폭증, 악성 파일, 긴 요청의 연결 고갈
- **ARCH 흐름**: 업로드·내보내기
- **ARCH 게이트·테스트**: 크기 상한 초과 거부
- **팩**: 없음

### TR-08 외부 연동
- **판별 신호**: 결제, 메일·SMS·모바일 푸시 발송, 서드파티 API, 소셜 로그인
- **PM 관점**: `연동 실패 | 외부가 실패·지연할 때 사용자에게 보이는 결과, 대체 방식`
- **PM 산출물**: P5 REJ(외부 실패) / P6 AC(대체 동작)
- **ARCH 결정**: 연동 경계(어댑터 위치), 시험용 대역, 시간 제한·재시도
- **ARCH 리스크**: 외부 장애의 전파, 연동 비밀키 노출
- **ARCH 흐름**: 연동 호출과 실패 처리
- **ARCH 게이트·테스트**: 시험용 대역으로 실패 경로 확인
- **팩**: 없음

### TR-09 화면
- **판별 신호**: 프로파일 §1 산출물 형태가 화면을 포함, 화면·페이지 요구
- **PM 관점**: `화면 상태 | 데이터 없음·오류·로딩·권한 없음일 때 표시`
- **PM 산출물**: P7 화면 목록·와이어프레임
- **ARCH 결정**: 화면 기술(서버 렌더링 / 클라이언트 앱 / 게임 클라이언트 등), 화면 데이터 계약 방식, 화면 갱신 방식
- **ARCH 리스크**: 화면이 서버 규칙을 중복 구현, 화면에 민감 정보 노출
- **ARCH 흐름**: 화면 렌더링·화면 데이터 조회
- **ARCH 게이트·테스트**: 화면 데이터 계약(PAGE)별 표시 확인
- **팩**: 없음

### TR-10 게임 규칙
- **판별 신호**: 승패, 점수, 라운드·턴, 플레이어 행동, 밸런스
- **PM 관점**: `게임 진행 | 시작·종료 조건, 라운드·턴 구조, 이탈·무승부 처리` / `판정 공정성 | 서버가 판정하는 것과 클라이언트가 보내는 것의 경계`
- **PM 산출물**: P3 게임 상태 흐름과 규칙 INV / P6 결과 판정 AC
- **ARCH 결정**: 판정 권위 위치(서버 권위 여부), 진행 방식(턴 처리 / 주기 갱신), 결과 저장
- **ARCH 리스크**: 클라이언트 조작, 비결정적 판정으로 재현 불가
- **ARCH 흐름**: 게임 시작·행동 처리·종료 판정
- **ARCH 게이트·테스트**: 같은 입력이면 같은 판정(결정성), 조작된 클라이언트 입력 거부
- **팩**: 없음

### TR-11 운영·관리자
- **판별 신호**: 관리자, 운영자, 대시보드, 통계, 강제 처리
- **PM 관점**: `운영 주체 | 운영자가 무엇을 보고 어떤 판단·조치를 하는가`
- **PM 산출물**: P4 D-004 관리자 역할 / P7 운영 화면
- **ARCH 결정**: 관리자 권한 모델은 코어 ADR-002에 포함, 관리 기능의 모듈 위치는 코어 ADR-001에 포함
- **ARCH 리스크**: 권한 상승, 운영 조치의 기록 누락
- **ARCH 흐름**: 운영 조치
- **ARCH 게이트·테스트**: 일반 사용자의 관리 기능 접근 거부
- **팩**: 없음

### TR-12 성능·캐시
- **판별 신호**: 응답 시간 수치, 조회량이 많은 기능, 캐시 언급
- **PM 관점**: `성능 목표 | 대상 기능, 수치, 측정 조건`
- **PM 산출물**: P6 NFR(성능 수치와 측정 조건)
- **ARCH 결정**: 캐시 방식·대상·만료·무효화 위치, 인덱스 방침
- **ARCH 리스크**: 오래된 데이터 노출, 무효화 누락
- **ARCH 흐름**: 캐시 조회·무효화
- **ARCH 게이트·테스트**: 상태 변경 후 캐시 무효화 확인, 성능 수치 측정
- **팩**: 없음

### TR-13 배포·운영 환경
- **판별 신호**: 배포, 서버 환경, 컨테이너, 운영 로그·지표
- **PM 관점**: `운영 환경 | 어디서 누가 실행하는가, 정상 동작을 어떻게 확인하는가`
- **PM 산출물**: P6 NFR(배포 후 확인 기준)
- **ARCH 결정**: 배포 구성(실행 명령, 환경 분리, 컨테이너 여부), 관측(로그·지표)
- **ARCH 리스크**: 환경별 설정 차이, 비밀값 유출
- **ARCH 흐름**: 배포·기동
- **ARCH 게이트·테스트**: 배포 구성으로 기동 확인
- **팩**: 없음

### TR-14 기존 결과물 변경
- **판별 신호**: 사이클이 C2 이상이고 이번 사이클 요구가 기존 항목(API·데이터·동작)을 바꿈, 또는 프로파일 §1 기존 결과물이 "파이프라인 밖의 기존 코드·문서" (상류 산출물을 고치지 않고 쓰기만 하면 TR-15)
- **PM 관점**: `호환성 | 기존 사용자·데이터·클라이언트에 미치는 영향, 바뀌면 안 되는 것`
- **PM 산출물**: P4 범위에 "유지해야 하는 기존 동작" 섹션 / P6 AC(기존 동작 회귀 없음)
- **ARCH 결정**: 인터페이스 호환·버전 정책, 스키마 변경과 기존 데이터 이전(코어 ADR-006에 포함)
- **ARCH 리스크**: 기존 클라이언트 깨짐, 데이터 손실
- **ARCH 흐름**: 데이터 이전
- **ARCH 게이트·테스트**: 기존 동작 회귀 테스트
- **팩**: 없음

### TR-15 상류 계약 소비
- **판별 신호**: 프로파일 §2에 `상류 산출물` 역할 문서(다른 제품·저장소의 API 명세·스키마 등)가 있고, 이번 결과물이 그 위에서 동작
- **PM 관점**: `상류 계약 | 상류에서 쓰는 기능의 범위, 상류에 없는 기능이 필요할 때 처리(상류 변경 요청 / 이번 범위에서 제외), 상류 실패·지연 시 사용자에게 보이는 결과`
- **PM 산출물**: P4 "상류에 요청할 변경" 목록(있으면 사용자 확인) / P5 REJ(상류 실패) / P6 AC(상류 계약대로 호출)
- **ARCH 결정**: 상류 호출 경계(클라이언트 어댑터 위치), 계약 고정 방식(버전·명세 사본), 상류 대역(시험용)
- **ARCH 리스크**: 상류 계약이 바뀌어 동작이 깨짐, 상류 장애의 전파
- **ARCH 흐름**: 상류 호출과 실패 처리
- **ARCH 게이트·테스트**: 고정한 상류 명세와 호출 일치 확인
- **팩**: 없음

### TR-16 레이팅·랭킹
- **판별 신호**: 실력 점수, 등급, 순위표, 전적
- **PM 관점**: `점수 규칙 | 점수 산정·갱신 시점, 초기값, 이탈·무효 경기의 반영, 순위 동점 처리`
- **PM 산출물**: P3 점수 갱신 규칙 INV / P6 AC(경기 결과에 따른 점수 변화)
- **ARCH 결정**: 점수 갱신의 원자성(결과 기록과 같은 트랜잭션 여부), 순위 조회 방식
- **ARCH 리스크**: 중복 반영, 순위 조회 부하
- **ARCH 흐름**: 결과 반영·점수 갱신
- **ARCH 게이트·테스트**: 같은 결과 두 번 반영 시 점수 한 번만 변화
- **팩**: 없음

### TR-17 데이터 보존·개인정보
- **판별 신호**: 개인정보 처리, 탈퇴, 보관 기간, 이용 기록, 미성년자
- **PM 관점**: `보존·파기 | 무엇을 얼마나 보관하는가, 탈퇴·파기 시 남기는 것과 지우는 것, 본인 데이터 열람`
- **PM 산출물**: P3 보존 기간 규칙 / P5 탈퇴·파기 흐름 / P6 AC(파기 후 조회 불가)
- **ARCH 결정**: 삭제 방식(물리 삭제 / 익명화), 보존 기간 처리 방식
- **ARCH 리스크**: 파기 누락, 로그·백업에 남는 개인정보
- **ARCH 흐름**: 탈퇴·파기
- **ARCH 게이트·테스트**: 파기 후 개인정보 조회 0
- **팩**: 없음
