## 2. 가정·모호성 목록 (영향 큰 순)

### ASM-001 (모호, 확정 Q-001) ← REQ-031, REQ-018, REQ-T03
- 내용: "정기구독"의 주기(매달 등)와 결제 방식(정기 자동결제 / 회차마다 결제)이 없다.
- 위험: 자동결제는 PG 계약·빌링 연동이 필요하고, 결제 실패·해지 정산 규칙이 늘어난다(D4). 데이터 모델의 핵심이라 되돌리기 비용이 크다.
- 질문: Q-001
- 영향 계층: [인프라] [모듈 협력 구조] → D-002, D-003 결정 카드로 이어짐

### ASM-002 (모호, 확정 Q-002) ← REQ-031, REQ-032, REQ-035
- 내용: 손편지를 "구독 신청 때 한 번" 쓰는지, "매 회차마다" 쓰는지 불명확. 촛불 상태(REQ-035~037)는 편지 1통 단위로 움직인다고 읽힌다.
- 위험: 회차와 편지의 관계가 정해지지 않으면 촛불·발송·코드의 단위가 흔들린다.
- 질문: Q-002
- 영향 계층: [모듈 협력 구조]

### ASM-004 (누락, 확정 Q-003) ← REQ-045, REQ-048
- 내용: "바로 깔끔하게 해지"할 때 이미 결제됐거나 책방지기가 편지를 읽는 중인 회차를 어떻게 할지 없음.
- 위험: 환불·발송 누락 분쟁(D4). 유예 단계 금지(REQ-045)와 충돌하지 않는 규칙이 필요.
- 질문: Q-003
- 영향 계층: [모듈 협력 구조]

### ASM-007 (누락, 확정 Q-004) ← REQ-017, REQ-018, REQ-034
- 내용: 장바구니로 산 일반 책 주문의 배송 현황 표시 방식이 없다. 촛불 연출은 구독 편지 흐름에만 정의됨.
- 위험: 일반 주문 상태 화면이 비어 있거나, 촛불 규칙을 억지로 적용하게 됨.
- 질문: Q-004
- 영향 계층: [어플리케이션]

### ASM-005 (누락, 확정 Q-005) ← REQ-010, REQ-013, REQ-053
- 내용: 책(상품)·책방지기 노트·테마를 누가 어떻게 등록·수정하는지 없음. 관리자 화면 요구(§4)는 구독 작업만 다룬다.
- 위험: 관리 화면을 임의로 추가하면 근거 없는 기능(D3), 빼면 운영 중 책 추가가 불가능.
- 질문: Q-005
- 영향 계층: [어플리케이션]

### ASM-006 (누락, 확정 Q-006) ← REQ-017, REQ-053
- 내용: 재고(수량)·품절 처리가 없다. 동네서점 특성상 한 권만 있는 책도 있을 수 있음.
- 위험: 없는 책이 팔리거나, 구독 매칭한 책과 일반 판매가 겹침.
- 질문: Q-006
- 영향 계층: [모듈 협력 구조]

### ASM-021 (모호, 확정 Q-007) ← REQ-041
- 내용: 6자리 코드(경우의 수 100만)를 손님이 직접 입력. 입력 실패 제한이 없다.
- 위험: 무차별 대입으로 남의 책·답장이 열릴 수 있음(D4). 코드는 해당 손님 계정에서만 유효하다고 전제(ASM-011 참고).
- 질문: Q-007
- 영향 계층: [모듈 협력 구조]

### ASM-003 (누락, 확정 D-004) ← REQ-018, REQ-056, REQ-021
- 내용: 소셜 로그인은 배송 주소를 주지 않는다. 배송지·연락처를 언제 받고 얼마나 보관할지 없음.
- 확정(D-004): 주문·구독 신청 시 입력받아 재사용 저장, 회원 탈퇴 시 삭제(법정 거래기록 보관 대상 제외). 개인정보 처리방침 고지 문구는 의뢰인 제공.
- 영향 계층: [어플리케이션] — P4에서 D-004 결정 카드 후보

### ASM-009 (누락, 자율 — 금액은 의뢰인 콘텐츠) ← REQ-018, REQ-031
- 내용: 책 가격 외 구독료·배송비 금액이 없음.
- 처리: 금액은 기능 범위가 아니라 콘텐츠다. 개발은 자리표시 금액으로 진행하고, 실제 금액은 의뢰인이 채운다. 범위 영향 없음 → 질문하지 않음.

### ASM-008 (암묵적 전제, 자율)
- 내용: 비회원은 메인·테마·목록·상세를 볼 수 있고, 장바구니·주문·구독·마이페이지는 로그인이 필요하다. 근거: REQ-020, REQ-021(가입 피로 최소화 = 둘러보기는 자유) — D-015

### ASM-010 (암묵적 전제, 자율)
- 내용: 촛불은 편지 1통 단위 3단계(어두움 → 촛불 켜짐 → 우체통 불빛). 책방지기가 편지를 처음 열 때 자동 전이, 되돌리지 않음. 손님 화면은 다시 열 때 반영되면 충분(실시간 여부는 →A-04). 근거: REQ-035~037, REQ-052 — D-010

### ASM-011 (암묵적 전제, 자율)
- 내용: 코드 입력 성공 전에는 손님 화면·응답 어디에도 책 표지·제목·답장 편지·엽서 사진이 나오지 않고 힌트 문장만 나온다. 코드는 그 발송을 받은 손님 계정에서만 유효. 근거: REQ-038, REQ-039, REQ-041, REQ-042 — D-011

### ASM-012 (암묵적 전제, 자율)
- 내용: 서가 메모는 언박싱된 책 1권당 1개, 100자 이하, 본인만 열람, 수정·삭제 가능, 날짜 = 작성(수정)일. 근거: REQ-043, REQ-044 — D-012

### ASM-013 (모호, 자율)
- 내용: 해지 화면의 "마지막 인사 편지"는 모든 손님에게 같은 문구 1개. 근거: REQ-046 — D-013

### ASM-014 (암묵적 전제, 자율)
- 내용: 주소록 엑셀은 관리자만, 대상은 "발송 대기"인 구독 회차와 일반 주문 모두(이름·주소·연락처). 일반 주문도 택배로 나가므로 포함(Q-004 답변으로 일반 주문은 상태 문구만 표시). 근거: REQ-056, ASM-003 — D-014

### ASM-015 (모호, 자율)
- 내용: KANT-C3은 "로그인·백엔드 등 범위 밖 작업 통제"를 묻지만 팀 결정(REQ-T03)은 이를 포함한다. C3은 범위 축소가 아니라 마일스톤 순서·타임박스로 증빙한다(PM 스킬 §0.3). — D-016

### ASM-016 (모호, 확정 D-001)
- 내용: KANT는 4일차 시연을 요구(REQ-T09). 전체 범위를 4일 안에 끝낼 수 있는지 미정. 의뢰인은 개발 기간·견적 제안을 요청(REQ-060).
- 처리: D-001 승인(4일 타임박스, PM-SCOPE §2). 견적(금액)은 PM 범위 밖으로 보고만 한다.

### ASM-017 (암묵적 전제, 자율)
- 내용: 관리자는 책방지기 1명. 로그인 수단이 카카오·네이버뿐이므로(REQ-021) 책방지기도 그중 하나로 로그인하고, 그 계정에만 관리자 권한을 준다(부여 방식 →A-07). — D-017

### ASM-018 (모호, 자율)
- 내용: 반응형 기준 360/768/1280px, 각 폭에서 가로 스크롤·글자 겹침·이미지 왜곡 없음. 기기의 "동작 줄이기" 설정 시 봉투·촛불 애니메이션 대신 정지 화면. 관리자 화면은 한 열 세로 배치, 가로 분할 없음. 근거: REQ-014~016, REQ-033, REQ-050, REQ-051 — D-018

### ASM-019 (암묵적 전제, 자율)
- 내용: 결제 실패·취소 시 주문은 "결제 대기"로 남고 장바구니는 비우지 않는다. 구독 편지는 결제 확정 전에는 책방지기 화면에 나타나지 않는다. 근거: REQ-018, REQ-031 — D-019

### ASM-020 (누락, 자율)
- 내용: 전자상거래 사이트로서 사업자 정보·환불 규정·개인정보 처리방침 고지 자리가 필요. 화면에 자리를 두고 문구는 의뢰인이 채움. — D-020
