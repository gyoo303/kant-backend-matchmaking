- 입력: PM-INV (REQ-001~060, REQ-T01~T08), UX-CTX-ORCH **미배포** (`docs/uiux/context/for-orchestrator.md` 없음)

## 2. 가정·모호성 목록

### ASM-001 (확정) ← REQ-031, REQ-T03
- 내용: 정기구독의 결제 방식이 없다. 매달 자동결제인지, 편지를 보낼 때마다 결제하는지 알 수 없다.
- 위험: 결제·구독 데이터 구조와 해지 처리가 통째로 달라진다. 자동결제는 PG 정기결제 계약(빌링키)이 따로 필요하다 (D4).
- 질문: Q-001
- 영향 계층: [인프라] [모듈 협력 구조]

### ASM-002 (확정) ← REQ-031, REQ-034~037
- 내용: 구독 주기·한 번에 받는 책 권수·구독료가 없다. "회차"의 정의가 없다.
- 위험: 촛불 상태(편지 1통 기준)와 발송 단위를 정할 수 없다.
- 질문: Q-002
- 영향 계층: [모듈 협력 구조]

### ASM-003 (전제) ← REQ-010~012, KANT-C5
- 내용: 책(상품)은 ID·이름·가격·이미지 URL·설명 + 테마(4개 중 1개)·책방지기 노트·저자·출판사 소개를 가진다. 책 1권은 테마 1개에 속한다.
- 위험: 한 책이 여러 테마에 걸치면 서가 화면·데이터가 달라진다. 낮음.
- 처리: [자율] P3에서 "책 1권 = 테마 1개"로 정의, decision-log 기록.

### ASM-004 (확정) ← REQ-050, REQ-053
- 내용: 책방지기가 책을 등록·수정하는 화면이 의뢰서에 없다. 재고 수량 관리 여부도 없다.
- 위험: 없으면 책 추가 때마다 개발자가 데이터를 직접 넣어야 한다(운영 부담). 재고가 없으면 품절 책이 주문될 수 있다.
- 질문: Q-003
- 영향 계층: [어플리케이션]

### ASM-005 (확정) ← REQ-015, REQ-016, REQ-034
- 내용: 일반 주문(장바구니 구매)의 배송 현황 표시가 없다. 창가 촛불은 구독 편지에만 해당하는 것으로 보인다. 택배사 연동은 원하지 않는다(REQ-034).
- 위험: 일반 주문 고객이 발송 여부를 알 수 없다.
- 질문: Q-004
- 영향 계층: [모듈 협력 구조]

### ASM-006 (확정) ← REQ-016
- 내용: 주문 취소·환불 정책과 처리 주체가 없다.
- 위험: 전자상거래법상 청약철회 대응 필요. 자동 환불은 PG 연동 범위를 키운다 (D4).
- 질문: Q-005
- 영향 계층: [인프라] [모듈 협력 구조]

### ASM-007 (확정) ← REQ-045~047
- 내용: 책방지기가 이미 편지를 읽는 중(촛불 켜짐)이거나 결제가 끝난 회차가 있을 때 해지하면 어떻게 되는지 없다.
- 위험: 결제했는데 책을 못 받거나, 해지했는데 결제되는 사고.
- 질문: Q-006
- 영향 계층: [모듈 협력 구조]

### ASM-008 (전제) ← REQ-020, REQ-021
- 내용: 비회원은 둘러보기만 하고, 장바구니·주문·구독·마이페이지는 로그인 후 쓴다.
- 처리: [자율] 소셜 로그인 2종이라 로그인 부담이 작고, 비회원 주문은 의뢰서에 없음.

### ASM-009 (확정) ← REQ-055
- 내용: 배송지·연락처를 언제 받고 얼마나 보관하는지 없다.
- 위험: 개인정보 최소 수집·보관 기간 고지 의무 (D4).
- 질문: Q-008 (2차 질문)
- 영향 계층: [모듈 협력 구조]

### ASM-010 (전제) ← REQ-035~037, REQ-052
- 내용: 창가 상태는 편지 1통(회차) 단위로 "어두움 → 촛불 → 우체통 불빛" 3단계이고, 책방지기가 관리자 화면에서 편지를 처음 열면 자동으로 촛불로 바뀌며 되돌리지 않는다.
- 처리: [자율] 원문 흐름 그대로. 반영 방식(실시간/새로고침)은 →ARCH A-04.

### ASM-011 (확정) ← REQ-041, REQ-054
- 내용: 6자리 코드는 회차 1개당 1개, 재사용 없음. 숫자 6자리면 100만 가지라 무차별 입력이 가능하다.
- 위험: 다른 사람의 책·답장 편지가 열릴 수 있다 (D4).
- 질문: Q-007
- 영향 계층: [모듈 협력 구조]

### ASM-012 (전제) ← REQ-044
- 내용: 서가 메모는 언박싱된 책 1권당 1개, 100자 이하, 본인만 열람, 수정·삭제 가능.
- 처리: [자율] "100자 정도"를 100자 상한으로 정의.

### ASM-013 (확정) ← REQ-046
- 내용: "마지막 인사 편지"가 모든 손님에게 같은 문구인지, 손님마다 책방지기가 쓰는지 없다.
- 처리: [자율] 공통 고정 문구 1개(사용자 제공 문구, US-18). 해지는 즉시 처리해야 하므로(REQ-047) 개별 작성 대기는 불가.

### ASM-014 (모호) ← REQ-055
- 내용: 주소록 엑셀의 대상(발송 대기 건만 / 전체 회원)과 다운로드 권한.
- 처리: [자율] 관리자만, 발송 대기 건만. 파일 형식은 →ARCH A-06.

### ASM-015 (모호) ← REQ-T03, REQ-T04, REQ-T07, KANT-C3
- 내용: KANT-C3은 "로그인 등 필수 범위를 벗어난 작업"을 통제하라고 하지만 팀 결정은 로그인·결제·구독을 포함한다. 시연은 4일차다.
- 처리: [자율] 범위를 줄이지 않고 마일스톤 순서(KANT 증빙 경로 M1 우선)와 타임박스로 통제 (P4, D-001에서 확인).

### ASM-016 (모호) ← REQ-053
- 내용: 손글씨 엽서 사진은 회차당 1장, 이미지 파일. 손님은 언박싱 후에만 본다.
- 처리: [자율] P5에서 개수·용량 한도를 정의.

### ASM-017 (전제) ← REQ-050~055
- 내용: 관리자는 책방지기 1명이며 본인도 소셜 로그인으로 들어온다. 관리자 권한은 특정 계정에 부여한다.
- 처리: [자율]. 권한 부여 방식은 →ARCH A-07.

### ASM-018 (모호) ← REQ-013, REQ-014, REQ-033, REQ-051
- 내용: 반응형 기준 폭, 애니메이션 길이, 관리자 화면 기기가 없다.
- 처리: [자율] 360/768/1280px 기준, 동작 줄이기 설정 시 애니메이션 대신 정지 화면, 관리자는 PC·태블릿 한 열 배치. P6 NFR로 정량화.

### ASM-019 (누락) ← REQ-016, REQ-031
- 내용: 결제 실패·취소 시 주문과 편지의 상태가 없다.
- 처리: [자율] 결제 대기로 남기고 장바구니 유지. 결제 확정 전 편지는 관리자 화면에 나타나지 않는다.

### ASM-020 (확정) ← (원문 없음, 법규)
- 내용: 통신판매 사이트에 필요한 사업자 정보·환불 규정·개인정보 처리방침 고지가 없다.
- 처리: 사용자 지시로 이번 범위에서는 기재하지 않는다(D-021). 실서비스 전 고지 필요 위험은 PM-SCOPE §5.

### ASM-021 (전제) ← REQ-016, REQ-T03
- 내용: PG 계약 전이므로 결제는 테스트 모드로 개발·시연한다. 카드 정보는 사이트가 저장하지 않는다. 같은 결제는 한 번만 확정한다.
- 처리: 실결제 전환 여부는 D-002(P4)에서 확인. PG 선택은 →ARCH A-01.

### ASM-022 (범위 밖) ← REQ-060
- 내용: 개발 기간은 P4 마일스톤으로 답한다. 견적(금액)은 PM 산출물 범위가 아니다.
- 처리: 사용자 보고만.
