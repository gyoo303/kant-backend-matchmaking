# 03. 도메인 정의 (PM-DOMAIN)

- 입력: PM-INV, PM-ASM(`## 답변` Q-001~Q-008), PM-DEC. UX-CTX-ORCH 미배포.
- 범위: 업무 규칙 수준. 테이블·컬럼·타입은 Architect가 정한다(식별자는 **후보**).

## 1. Use Case 한 문장 (KANT-C1)
**대전 어은동 동네서점 '우분투북스'가 자연·식문화·생태·로컬 4개 테마의 책을 판매하고, 독자가 손편지를 보내면 책방지기가 직접 골라 보내는 블라인드 북 구독을 운영하는 온라인 책방.** 대상은 빠른 배송보다 느린 관계와 기다림을 원하는 독자(스마트폰 위주, 밤에는 태블릿·노트북)다. (REQ-001~004, REQ-010, REQ-013, REQ-031)

## 5. 비즈니스 상태 흐름

### 5.1 주문 (Order)
| 상태 | 코드 후보 | 들어오는 조건 | 전이 주체 |
|---|---|---|---|
| 결제 대기 | `pending_payment` | 회원이 주문서 제출 | 회원 |
| 주문 접수 | `paid` | 결제 확정 | 결제 대행사 → 시스템 |
| 취소 요청 | `cancel_requested` | `paid`에서 회원이 취소 요청 | 회원 |
| 주문 접수(복귀) | `paid` | `cancel_requested`에서 회원이 [취소 요청 철회] 또는 책방지기가 [취소 거절] | 회원 / 책방지기 |
| 환불 완료 | `refunded` | `cancel_requested`에서 책방지기 환불 처리 | 책방지기 |
| 발송됨 | `shipped` | `paid`에서 책방지기 발송 처리 | 책방지기 |
| 결제 전 취소 | `cancelled` | `pending_payment`에서 회원 탈퇴 시 자동 | 시스템 |

- 결제 실패·창 닫기: `pending_payment` 유지, 장바구니 유지 (D-020).
- `shipped`, `refunded`, `cancelled`는 끝 상태. 발송 후 취소 요청 불가 (Q-005).
- 취소 요청은 철회·거절로 `paid`에 돌아갈 수 있다(사용자 지시 2026-10-21, D-029). 거절되면 회원 화면에 "책방지기가 취소 요청을 받지 않았어요. 책은 그대로 보내드려요"가 보인다.
- 회원 화면 표시는 "주문 접수 → 발송됨" 2단계 + 취소 요청·환불 완료 안내 (Q-004).

### 5.2 편지 구독 (Subscription)
| 상태 | 코드 후보 | 조건 | 전이 주체 |
|---|---|---|---|
| 진행 중 | `active` | 첫 회차 결제 확정 | 시스템 |
| 마무리됨 | `ended` | 해지 화면에서 [구독을 마무리합니다] | 회원 |

- 마무리 후 새 편지를 쓸 수 없다. 다시 편지를 보내면 새 구독이 시작된다 (D-003 A: 첫 편지 결제 확정 = 구독 시작).
- 마무리해도 결제 확정된 진행 중 회차는 발송·언박싱까지 이어진다 (Q-006, INV-14).

### 5.3 회차 (SubscriptionRound) = 창가 등불
| 상태 | 코드 후보 | 회원 화면(창가) | 들어오는 조건 | 전이 주체 |
|---|---|---|---|---|
| 결제 대기 | `pending_payment` | (창가 없음, 결제 안내) | 우체통에 편지 넣기 | 회원 |
| 편지 도착 | `arrived` | 창문 어두움 + "편지가 서점에 도착했어요" | 결제 확정 | 결제 대행사 → 시스템 |
| 읽는 중 | `reading` | 창가 촛불 켜짐 + "책방지기가 당신의 편지를 읽고 있어요" | 책방지기가 서재 작업 화면에서 편지를 처음 엶 | 책방지기(자동) |
| 발송됨 | `shipped` | 촛불 꺼짐 + 우체통 불빛 + "책이 서점 문을 나섰습니다" + 실루엣·티저·코드 입력 | 책·답장·티저 입력 후 [발송] → 코드 자동 생성 | 책방지기 |
| 언박싱됨 | `unboxed` | 표지·제목·답장·엽서 공개, 서가 메모 가능 | 회원이 올바른 코드 입력 | 회원 |
| 취소됨 | `cancelled` | 취소 안내 | 결제 대기에서 회원이 거둠·탈퇴·구독 마무리, 또는 취소 요청 중 회차를 책방지기가 환불 처리 (D-002) | 회원 / 책방지기 / 시스템 |

- 앞으로만 간다(INV-09). 결제 실패 시 `pending_payment` 유지.
- 서재 작업 화면 대상은 `arrived`, `reading`만 (D-020, INV-18).
- **취소 요청 표시 (`cancelRequested`, 후보)**: 회차의 취소 요청은 상태가 아니라 `arrived`·`reading` 회차에 붙는 **표시**다. 창가 등불 상태를 되돌리지 않기 위해서다(INV-09, D-029).

| 표시 변화 | 조건 | 주체 | 결과 |
|---|---|---|---|
| 없음 → 취소 요청 | `arrived`·`reading` 회차에서 [취소 요청] | 회원 | 창가 상태 유지 + "취소 요청 중" 문구. [발송] 막힘, 주소록 제외 (INV-17, INV-20) |
| 취소 요청 → 없음 | [취소 요청 철회] | 회원 | 원래대로 진행 |
| 취소 요청 → 없음 | [취소 거절] | 책방지기 | 원래대로 진행, 회원 창가에 "책방지기가 취소 요청을 받지 않았어요. 책은 그대로 보내드려요" |
| 취소 요청 → 회차 `cancelled` | [환불] 성공 | 책방지기 | 결제 환불, 진행 중 회차 자리 비움 |

- 취소 요청 중에도 책방지기는 편지를 열 수 있고, 처음 열면 `arrived` → `reading`이 된다(표시는 유지).

### 5.4 진행 중 회차 (용어 정의, INV-12)
| 용어 | 포함 상태 | 쓰는 곳 |
|---|---|---|
| **진행 중 회차** | `pending_payment`, `arrived`, `reading` (취소 요청 표시 여부 무관) | 새 편지 제한(INV-12, US-11) |
| **결제 확정된 진행 중 회차** | `arrived`, `reading` | 해지 후 발송 계속(INV-14), 탈퇴 제한(US-05), 회차 취소 요청(US-20) |
