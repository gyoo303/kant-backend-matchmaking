# 03. 도메인 정의 (P3)

- 입력: REQ-001~129, ASM-01~14 (Q-01~04 답변 반영)
- 식별자는 코드 이름 **후보**다. 파일·모듈 배치는 ARCH가 정한다.

## 1. Use Case 한 문장 정의 (RC-01)

로그인한 회원에게, 2vs2(4명 고정) 공개 방을 만들거나 찾아 참가하고 방 안에서 팀을 바꾼 뒤 방장이 '게임 시작'을 누르면 결과 판정 없이 방이 해산되는 **매치메이킹 시연 서비스**를 제공한다. 정원·한 방 제한·팀 정원·방장 위임·소프트 삭제 규칙은 도메인 객체가 스스로 검사한다. (REQ-006, REQ-007, REQ-003)

## 2. 액터 & 목표

| 액터 | 목표 | 근거 |
|---|---|---|
| 비로그인 방문자 | 회원가입·로그인만 한다. 그 밖의 화면은 로그인 화면으로 이동 | REQ-010, D-005 |
| 회원(참가자) | 방 찾기·생성·참가·본인 팀 변경·나가기, 본인 이용 이력 확인 | REQ-011~012, REQ-017, Q-02 |
| 방장 | 참가자 역할 + 제목 변경, 게임 시작(해산) | REQ-013, REQ-030, Q-01 |

- 서비스 전체 운영자는 없다(REQ-008, REQ-125). 방장은 특정 방의 역할이며 위임으로 바뀐다(REQ-043).

## 4. 도메인 클래스별 규칙

규칙 위반은 도메인이 `ValueError`(또는 그 하위 예외)로 거부한다(REQ-T05, REQ-T12). "거부" 열이 도메인이 스스로 검사하는 규칙이다.

### 4.1 `User`

| 시점 | 규칙 | 근거 |
|---|---|---|
| 생성자 | `login_id`: 4~20자, 영문 소문자·숫자만 | Q-04 |
| 생성자 | `nickname`: 앞뒤 공백 제거 후 2~12자, 한글·영문·숫자만 | Q-04, D-011 |
| 생성 전 검증 | 원문 비밀번호 8자 이상 (`User.validate_raw_password()`), 도메인은 해시만 보관 | Q-04, REQ-021 |
| 응용 서비스 협력 | 아이디·닉네임 중복은 저장소 조회 결과로 거부 | Q-04 |

- 비밀번호 해시는 어떤 응답에도 나가지 않는다(REQ-022, INV-13).

### 4.2 `TokenBlacklist`

| 시점 | 규칙 | 근거 |
|---|---|---|
| 생성자 | 토큰 식별 정보와 만료 시각이 있어야 한다 | REQ-059 |
| 행위 `is_blocked(token)` | 등록된 토큰이면 인증 거부(401) | REQ-059, REQ-060 |

### 4.3 `Room`

| 행위 메서드 후보 | 거부 규칙 | 결과 | 근거 |
|---|---|---|---|
| `Room.create(title, creator, current_participation, now)` | 제목 규칙 위반 / 생성자가 이미 어떤 방에 참가 중 | 활성 방, A·B 두 팀 생성, 생성자 = 방장, 생성자 참가(입장 순서 1, A팀) | REQ-024~029, REQ-033, Q-03 |
| `Room.rename(requester_id, title)` | 삭제된 방 / 요청자가 현재 방장이 아님 / 제목 규칙 위반 | 제목 변경 | REQ-030, REQ-031 |
| `Room.join(user, current_participation, now)` | 삭제된 방 / 정원(4명) 마감 / 다른 방에 참가 중. 같은 방에 이미 참가 중이면 거부하지 않고 기존 참가 반환 | 새 참가(다음 입장 순서, A팀에 자리가 있으면 A팀, 없으면 B팀) | REQ-031, REQ-033~035, D-006, Q-03, D-024 |
| `Room.change_team(user_id, target)` | 삭제된 방 / 요청자가 현재 참가자가 아님 / 대상 팀 2명 마감(`Team.add`가 거부). 이미 그 팀이면 변경 없음 | 원래 팀에서 빠지고 대상 팀에 들어감 | REQ-031, REQ-036, Q-02 |
| `Room.leave(user_id, now)` | 요청자가 이 방의 현재 참가자가 아님 | 퇴장 시각 기록. 방장이면 남은 참가자 중 입장 순서가 가장 빠른 사람에게 위임. 마지막이면 소프트 삭제(`EMPTY`) | REQ-041~044 |
| `Room.start_game(requester_id, now)` | 삭제된 방(반복 요청 포함) / 요청자가 현재 방장이 아님 / A팀·B팀이 각각 정확히 2명이 아님 | 소프트 삭제(`GAME_STARTED`), 전원 퇴장 시각 기록. 승패·결과 데이터는 만들지 않음 | REQ-048~052, Q-01, REQ-001 |
| `Room.is_full`, `Room.available_seats` | — | 목록 '정원 마감'·빈자리 필터 판단 | REQ-081, REQ-087 |

- 한 회원 한 방 제한(REQ-033)은 다른 방의 상태가 필요하므로, 응용 서비스가 회원의 현재 참가를 조회해 `current_participation`으로 넘기고 **판단은 도메인이** 한다. 동시 요청에서의 보장(DB 잠금·제약)은 도전 A에서 추가한다(D-018, REQ-107).
- 정원(4)과 팀당 정원(2)은 생성 입력이 아니라 도메인 상수다(`Room.CAPACITY`, `Team.CAPACITY`, REQ-024, REQ-028).

### 4.4 `Team` (D-023)

| 행위 메서드 후보 | 거부 규칙 | 결과 | 근거 |
|---|---|---|---|
| 생성자 | 편(`A`·`B`)이 있어야 한다 | 팀원 0명 | REQ-036 |
| `Team.add(participation)` | 팀원이 이미 2명 / 종료된 참가 기록 | 팀원에 추가, 참가 기록의 편을 이 팀으로 | REQ-036, INV-03 |
| `Team.remove(participation)` | — | 팀원에서 뺌(나가기·팀 이동·게임 시작) | REQ-036, REQ-041 |
| `Team.is_full`, `Team.count` | — | 배정·이동·게임 시작 조건 판단 | INV-03, INV-08 |

- 팀은 방을 떠나 따로 존재하지 않는다. 방 생성 때 A·B 두 팀이 함께 생기고, 방이 삭제돼도 남는다(보관).

### 4.5 `Participation`

| 행위 메서드 후보 | 거부 규칙 | 결과 | 근거 |
|---|---|---|---|
| 생성자 | 입장 시각·입장 순서·팀이 있어야 한다 | 참가 중 | REQ-040 |
| `Participation.end(now)` | 이미 종료된 기록 | 퇴장 시각 기록(입장 시각 이후) | REQ-041, REQ-049 |
| `Participation.is_current` | — | 퇴장 시각이 없으면 참가 중 | REQ-054 |

- 종료된 기록은 이용 로그로 보관되고 다시 열지 않는다. 재입장은 새 기록·새 입장 순서다(REQ-046, D-025).
- 이용 로그는 삭제·수정하지 않는다(REQ-058). 회원의 이용 기록 = 참가 중 기록(최대 1건) + 이용 로그.
- 이용 기록에는 화면·응답에 내보내는 별도 기록 번호가 없다(D-025).

## 5. 비즈니스 상태 흐름

### 5.1 방 (`Room`)

| 현재 상태 | 이벤트 | 전이 주체 | 다음 상태 | 근거 |
|---|---|---|---|---|
| — | 방 생성 | 회원(생성자) | 활성 | REQ-029 |
| 활성 | 참가·팀 변경·제목 변경·일반 퇴장·방장 퇴장(남은 사람 있음) | 참가자 / 방장 | 활성 | REQ-030, REQ-036, REQ-042, REQ-043 |
| 활성 | 마지막 참가자 퇴장 | 참가자 | 삭제됨(`EMPTY`) | REQ-044 |
| 활성 (A·B 각 2명) | 게임 시작 | 방장 | 삭제됨(`GAME_STARTED`) | REQ-049, Q-01 |
| 삭제됨 | 모든 변경 요청 | — | 거부 (되돌릴 수 없음) | REQ-031, REQ-058 |

### 5.2 참가 (`Participation`)

| 현재 상태 | 이벤트 | 다음 상태 | 근거 |
|---|---|---|---|
| — | 방 생성·참가 | 참가 중 | REQ-029, REQ-035 |
| 참가 중 | 본인 팀 변경 | 참가 중 (팀만 바뀜) | REQ-036 |
| 참가 중 | 나가기 | 종료 | REQ-041 |
| 참가 중 | 게임 시작(해산) | 종료 | REQ-049 |
| 종료 | — | 이용 로그로 보관, 변경 없음 (재입장은 새 기록) | REQ-046, D-025 |

- 로그아웃·브라우저 종료·폴링 중단은 상태를 바꾸지 않는다(REQ-038, REQ-091).

### 5.3 함께 처리되는 업무 단위

방 생성, 참가, 나가기, 게임 시작은 각각 하나의 업무 단위로 모두 저장되거나 모두 되돌려진다(REQ-071, REQ-105).
