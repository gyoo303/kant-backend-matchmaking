# 03. 도메인 정의 (P3)

- 입력: `01-requirements-inventory.md`, `02-assumptions-questions.md`(Q-01~07 답변), `decision-log.md`(D-005~007)
- 코드 식별자는 **후보**다. 최종 이름과 파일 위치는 Architect가 확정한다. 규칙이 도메인 객체 안에 있어야 한다는 것은 고정이다(REQ-003, REQ-T05).

## 1. Use Case 한 문장 정의 (RC-01)

회원(플레이어)에게, 원하는 인원 모드의 대기열에 등록하면 정원이 찬 순서대로 매치를 확정해 주고 점프 5회 선착 게임으로 승패를 가려 주는 매칭 서비스를, 운영자에게는 대기열과 게임을 지켜보고 봇으로 시연을 채울 수 있는 대시보드를 제공한다. (REQ-002, REQ-003, REQ-007)

## 2. 액터와 목표

| 액터 | 목표 | 근거 |
|---|---|---|
| 회원(플레이어) | 가입·로그인, 모드를 골라 대기, 취소, 게임 참여, 결과·히스토리 확인 | REQ-006 |
| 운영자 | 대기열·진행 중 게임 모니터링, 봇 투입, 이벤트 로그 확인, 끝나지 않는 게임 강제 종료, (도전 B) 다운로드 | REQ-007, Q-02 |
| 테스트 봇 | 회원과 같은 규칙으로 대기열에 등록되고 게임이 시작되면 자동으로 점프 | REQ-010, Q-01 |
| 비로그인 방문자 | 로비의 모드별 대기 인원, 매치 히스토리 목록 열람 | REQ-011 |

## 4. 도메인 클래스별 규칙

생성자 검증과 행위 메서드의 거부 규칙이다. 거부는 규칙 위반 예외(→ HTTP 400), 대상 없음은 별도 예외(→ 404)로 나뉜다(REQ-032, REQ-T12). 권한(운영자 전용)은 응용 계층에서 확인한다(§6).

### 4.1 User

| 구분 | 규칙 | 거부 조건 | 근거 |
|---|---|---|---|
| 생성자 | 닉네임 2~12자, 한글·영문·숫자 | 범위 밖 길이, 허용하지 않는 문자 | D-005 |
| 생성자 | 역할은 `UserRole` 중 하나, 일반 가입은 `PLAYER` | — | REQ-009 |
| 생성자 | 비밀번호 해시는 비어 있지 않다 | 빈 해시 | REQ-018 |
| `RawPassword` 생성자 | 4자 이상 | 4자 미만 | REQ-016, Q-05 |
| 규칙(저장 시) | 닉네임은 전체 회원에서 유일 | 이미 쓰는 닉네임 | REQ-015 |

### 4.2 MatchQueue

| 구분 | 메서드 후보 | 규칙 / 거부 조건 | 근거 |
|---|---|---|---|
| 생성자 | `MatchQueue(mode, capacity, waiting_count)` | 정원은 모드에 맞는 값(6/10/20), 1 이상 / 대기 인원은 0 이상 정원 이하 | REQ-019, REQ-020 |
| 행위 | `join(user_id, player_status, now) -> QueueTicket` | `player_status`가 `IDLE`이 아니면 거부(이미 대기 중·게임 중). 성공 시 대기 인원 +1 | REQ-017, REQ-022, Q-03 |
| 행위 | `leave(ticket)` | 이 대기열의 `WAITING` 티켓만. 성공 시 대기 인원 -1 | REQ-023 |
| 조회 | `is_full()` | 대기 인원 = 정원 | REQ-021 |
| 행위 | `take_full_group(waiting_tickets) -> 참가 순서 목록` | 가득 차지 않았으면 거부. 대기 순서(등록 시각)대로 정원만큼 꺼내고 대기 인원을 그만큼 줄인다 | REQ-021 |

### 4.3 QueueTicket

| 구분 | 메서드 후보 | 규칙 / 거부 조건 | 근거 |
|---|---|---|---|
| 생성자 | `QueueTicket(user_id, mode, enqueued_at)` | 상태는 `WAITING`으로 시작 | REQ-033 |
| 행위 | `cancel(requester_id)` | 본인이 아니면 거부 / `WAITING`이 아니면 거부(확정·취소된 티켓) | REQ-023, REQ-024 |
| 행위 | `mark_matched(match_id)` | `WAITING`이 아니면 거부 (취소된 티켓은 매치에 못 들어감 = 유령 플레이어 방지) | REQ-021, REQ-053 |
| 행위 | `expire(now, timeout_seconds)` (도전 D) | `WAITING`이고 마지막 응답 후 30초가 지났을 때만 | REQ-035, Q-07 |

### 4.4 Match / MatchParticipant

| 구분 | 메서드 후보 | 규칙 / 거부 조건 | 근거 |
|---|---|---|---|
| 생성 | `Match.start(mode, ordered_user_ids, now)` | 참가자 수 = 모드 정원 / 대기 순서대로 A, B 팀에 번갈아 배정 / 상태 `PLAYING`, 시작 시각 기록 | REQ-021, REQ-025, REQ-026 |
| 행위 | `record_jump(user_id, now)` | `PLAYING`이 아니면 거부 / 참가자가 아니면 거부 / 점프 수 +1 / 5회를 처음 채우면 그 참가자를 개인 승자, 그 팀을 승리 팀으로 정하고 `FINISHED`(`WIN`), 종료 시각 기록 | REQ-027, REQ-028, REQ-029 |
| 행위 | `force_finish(now)` | `PLAYING`이 아니면 거부 / 승자 없이 `FINISHED`(`FORCED`), 종료 시각 기록 | Q-02 |
| 조회 | `duration()` | 종료 시각 - 시작 시각 (종료 전에는 현재까지 경과) | REQ-030 |
| 조회 | `result_for(user_id)` | 개인 승리 여부, 팀 승리 여부 | REQ-042 |

### 4.5 BlacklistedToken

| 구분 | 메서드 후보 | 규칙 / 거부 조건 | 근거 |
|---|---|---|---|
| 생성자 | `BlacklistedToken(token_id, expires_at)` | 토큰 식별 값은 비어 있지 않다 | REQ-031 |
| 규칙(저장 시) | 같은 토큰은 한 번만 등록 | 이미 등록된 토큰의 재로그아웃 | REQ-031 |

### 4.6 EventLog

| 구분 | 규칙 | 근거 |
|---|---|---|
| 생성자 | 종류(등록·취소·매치 확정·게임 종료·로그인·로그아웃), 행위자, 발생 시각, 관련 대상(모드·매치)을 가진다. 만든 뒤 바뀌지 않는다 | REQ-049, D-007 |

### 4.7 PlayerStatus 판정

- 회원에게 `WAITING` 티켓이 있으면 `WAITING`, `PLAYING` 매치의 참가자이면 `PLAYING`, 둘 다 아니면 `IDLE`.
- 판정에 필요한 티켓·매치 조회는 응용 계층이 하고, 결과를 `MatchQueue.join()`에 넘긴다. 도메인은 넘겨받은 값으로 규칙만 검사한다.

## 5. 비즈니스 상태 흐름

### 5.1 QueueTicket

| 현재 상태 | 이벤트 | 다음 상태 | 실행 주체 | 근거 |
|---|---|---|---|---|
| (없음) | 대기열 등록 | `WAITING` | 회원, 봇(운영자 투입) | REQ-033 |
| `WAITING` | 본인 취소 | `CANCELLED` | 회원 본인 | REQ-034 |
| `WAITING` | 정원 충족 | `MATCHED` | 시스템 | REQ-021 |
| `WAITING` | 응답 없음 30초 (도전 D) | `TIMED_OUT` | 시스템 | REQ-035, Q-07 |
| `CANCELLED` / `MATCHED` / `TIMED_OUT` | (모든 이벤트) | 변하지 않음 | — | REQ-023 |

### 5.2 Match

| 현재 상태 | 이벤트 | 다음 상태 | 실행 주체 | 근거 |
|---|---|---|---|---|
| (없음) | 정원 충족 → 매치 확정 | `PLAYING` (확정과 동시에 시작) | 시스템 | REQ-026 |
| `PLAYING` | 점프 (5회 미만) | `PLAYING` | 참가자, 봇(자동) | REQ-027, Q-01 |
| `PLAYING` | 점프 5회 선착 | `FINISHED` (`WIN`) | 참가자, 봇 | REQ-028 |
| `PLAYING` | 강제 종료 | `FINISHED` (`FORCED`, 승자 없음) | 운영자 | Q-02 |
| `FINISHED` | (모든 이벤트) | 변하지 않음 | — | REQ-029 |

### 5.3 PlayerStatus (회원 기준)

`IDLE` → (등록) → `WAITING` → (정원 충족) → `PLAYING` → (매치 종료) → `IDLE`
`WAITING` → (취소 / 타임아웃) → `IDLE` → (바로 재등록 가능, Q-03)
도전 D: `PLAYING` 중 연결이 끊겼다가 다시 로그인하면 진행 중 매치로 돌아간다(상태는 그대로 `PLAYING`) (REQ-036)
