## 3. 범위 통제 근거

### 3.1 필수를 먼저 끝낸다
- DB·BE·FE·QA 구현은 필수(M2~M5) 티켓만 진행한다. 도전(M6) 티켓은 필수 완료(10일차, M5) 뒤, **사용자가 따로 요청할 때만** 착수한다. 11일차가 끝나면 남은 도전은 중단한다(D-002, D-018).
- 동시 요청 무결성(방 행 잠금, 한 회원 한 방 부분 유니크 인덱스)은 도전 A다. 필수 범위는 순차 요청에서 도메인 규칙으로 INV-01~08을 지킨다(D-018).

### 3.2 요구사항에 없는 기능은 Won't
- 원문과 발제에 근거가 없는 기능은 넣지 않는다. 특히 게임 결과·승패는 팀 결정으로 제외됐다(REQ-001).
- 미복귀 사용자가 자리·방장 역할을 붙잡는 문제(REQ-039)는 알려진 제약으로 두고, 정리 기능은 만들지 않는다(D-004).

### 3.3 외부 연동은 상태 변경·로그로 대체
- 실제 게임 서버 대신 게임 시작 = 방 소프트 삭제·참가 해제라는 상태 변경으로 끝낸다(REQ-049).
- 알림이 필요하면 로그로 대신한다(REQ-T19).
- 실시간 갱신은 하지 않는다. 화면은 진입·[새로고침]·조건 변경·본인 동작 때만 조회한다. 자동 조회·WebSocket·SSE는 쓰지 않는다(D-026, REQ-129).
