# 05. 사용자 스토리 & 기능 명세 (PM-US)

- 입력: PM-INV, PM-ASM(`## 답변`), PM-DOMAIN(용어 §3, 상태 §5, INV §6), PM-SCOPE(마일스톤 §3), PM-DEC(D-001~004 승인, 자율 D-010 이후)
- 형식: `US-xx: [액터]로서, [목표]를 위해, [행동]하고 싶다.` + 근거 + 마일스톤 → 정상 흐름 / 거부 시나리오(REJ) / 관련 INV
- 화면 구성은 PM-SCR, 수용 기준은 PM-AC가 이 ID를 그대로 쓴다.

## M1 쇼핑 기반

### US-01: 방문자로서, 이 책방이 어떤 곳인지 느끼기 위해, 메인에서 책방 소개와 4개 테마를 보고 싶다.
- 근거: REQ-001, REQ-002, REQ-004, REQ-010, D-021 · 마일스톤 M1
- 정상 흐름
  1. 메인(`/`)에 들어오면 Header(로고, 테마 서가·편지 구독·장바구니·로그인/마이페이지 링크), 책방 소개 글, 테마 4개(자연·식문화·생태·로컬) 진입 카드, 책방지기 추천 책 몇 권(ProductCard), Footer가 보인다.
  2. 테마 카드를 누르면 전체 새로고침 없이 해당 테마 서가(US-02)로 이동한다.
  3. Footer에는 책방 이름과 사이트 내 링크만 있다. 사업자 정보·환불 규정·개인정보 처리방침은 기재하지 않는다(D-021).
- 거부 시나리오
  - REJ-01 책 데이터를 불러오지 못하면: 화면이 멈추지 않고 소개·테마 영역은 보이며 추천 영역에 "책을 불러오지 못했어요" 안내가 나온다.
- 관련 INV: —

### US-02: 방문자로서, 마음에 맞는 책을 찾기 위해, 테마를 골라 그 테마의 책들을 차분히 둘러보고 싶다.
- 근거: REQ-010, REQ-011, KANT-R5, R7 · M1
- 정상 흐름
  1. 상품 목록(`/products`)에서 테마 4개 선택지와 "전체"가 보이고, 기본은 전체다.
  2. 테마를 고르면 전체 새로고침 없이 그 테마의 책만 카드 목록으로 바뀐다. 선택한 테마는 주소에 남아 공유·뒤로 가기가 된다.
  3. 카드에는 표지, 제목, 저자, 가격, 테마가 보이고, 재고 0이면 "품절" 표시가 붙는다.
  4. 카드를 누르면 상세(US-03)로 이동한다.
  5. "차분히 펼쳐짐"(REQ-011): 목록이 바뀔 때 카드가 짧은 페이드로 나타난다(PM-AC NFR). 동작 줄이기 설정이면 전환 없이 바로 보인다.
- 거부 시나리오
  - REJ-02 테마에 책이 없으면: "이 서가는 아직 비어 있어요" 안내와 다른 테마 링크.
  - REJ-03 주소의 테마 값이 4개가 아니면: 전체 목록을 보여 준다(오류 화면 없음).
- 관련 INV: INV-01, INV-05

### US-03: 방문자로서, 책방지기가 왜 이 책을 권하는지 알기 위해, 책 상세에서 책방지기 노트를 가장 먼저 읽고 싶다.
- 근거: REQ-012, KANT-R6, R9, C14 · M1
- 정상 흐름
  1. 상세(`/products/[id]`)에서 맨 위에 책방지기 노트가 큰 글씨로 보인다.
  2. 그 아래 표지, 제목, 저자, 가격, 테마, [장바구니 담기]가 보인다.
  3. 출판사 소개는 그 아래 접힌 영역으로 있고, 내용이 없으면 영역이 없다.
  4. [장바구니 담기]: 로그인 회원이면 담기(US-07), 비회원이면 로그인으로 안내 후 다시 이 상세로 돌아온다.
- 거부 시나리오
  - REJ-04 없는 ID: 화면이 멈추지 않고 "상품을 찾을 수 없습니다" + 목록으로 가는 링크 (KANT-C14).
  - REJ-05 품절(재고 0): [장바구니 담기]가 비활성, "품절" 안내.
- 관련 INV: INV-02, INV-05

### US-04: 방문자로서, 스마트폰·태블릿·노트북 어디서든 편히 읽기 위해, 화면이 깨지거나 글씨가 엉키지 않기를 원한다.
- 근거: REQ-013, REQ-014, KANT-R8, C9, C10, D-019 · M1
- 정상 흐름
  1. 360px·768px·1280px 폭에서 가로 스크롤 없이 모든 화면이 배치된다.
  2. 목록은 폭에 따라 열 수가 바뀌는 균일한 간격의 격자다.
  3. 표지 이미지는 비율이 유지되고 찌그러지지 않는다(잘라 채우기).
  4. 긴 글(노트·편지)은 한 줄 길이가 읽기 편하게 제한된다.
- 거부 시나리오
  - REJ-06 이미지 주소가 깨졌으면: 빈 칸 대신 대체 표지(책방 기본 이미지)가 같은 비율로 보인다.
- 관련 INV: —

## M2 회원·관리자 기반

### US-05: 회원으로서, 번거로운 가입 없이 들어오기 위해, 카카오나 네이버로 로그인하고 마이페이지를 쓰고 싶다.
- 근거: REQ-020, REQ-021, D-004, D-011 · M2
- 정상 흐름
  1. 로그인 화면에는 [카카오로 시작하기], [네이버로 시작하기] 두 버튼만 있다.
  2. 처음 로그인하면 별도 입력 없이 회원이 되고, 로그인 전에 보던 화면으로 돌아온다.
  3. 마이페이지에서 주문 현황(US-09), 편지 구독·창가(US-12), 나의 서가(US-17), 기본 배송지 수정, 로그아웃, 회원 탈퇴를 고른다.
  4. 회원 탈퇴 시 PM-DOMAIN §7 표대로 처리된다: 기본 배송지·손편지·답장·엽서·서가 메모·작별 안부·장바구니는 즉시 삭제, 결제 대기 주문·회차는 자동 취소, 주문·회차·결제 거래 기록(배송지 사본 포함)은 5년 보관 후 삭제. 이어서 로그인이 해제된다(D-004, D-030).
- 거부 시나리오
  - REJ-07 소셜 로그인 취소·실패: 로그인 화면으로 돌아와 "로그인을 마치지 못했어요. 다시 시도해 주세요" 안내.
  - REJ-08 비회원이 장바구니·주문·편지·마이페이지에 들어오면: 로그인 화면으로 안내, 로그인 후 원래 화면으로 복귀.
  - REJ-09 결제 확정된 진행 중 회차(`arrived`·`reading`, PM-DOMAIN §5.4)나 발송 전 결제 완료 주문(`paid`·`cancel_requested`)이 있으면 탈퇴 불가, 이유 안내.
- 관련 INV: INV-03, INV-19

### US-06: 책방지기로서, 개발자 없이 서가를 꾸리기 위해, 책을 등록·수정하고 재고 수량을 바꾸고 싶다.
- 근거: REQ-A01, REQ-A02, REQ-005, REQ-050, D-023 · M2
- 정상 흐름
  1. 관리자 메뉴의 책 관리에서 책 목록(제목, 테마, 가격, 재고)을 본다.
  2. [새 책 등록]: 제목, 저자, 가격, 테마(4개 중 선택), 표지 이미지, 짧은 설명, 책방지기 노트, 출판사 소개(선택), 재고를 입력하고 저장한다.
  3. 책을 골라 같은 항목을 수정한다. 재고를 0으로 하면 판매 중지(품절)가 된다. 삭제 기능은 없다.
  4. 한 열 세로 배치이며 저장 결과가 "저장했어요"로 보인다.
- 거부 시나리오
  - REJ-10 필수 항목 누락, 가격·재고가 음수·소수: 저장하지 않고 해당 칸 옆에 이유 표시.
  - REJ-11 관리자가 아닌 계정이 관리자 화면 주소로 접근: 접근 거부(메인으로 이동 또는 권한 없음 안내).
- 관련 INV: INV-01, INV-05, INV-15

## M3 구매

### US-07: 회원으로서, 고른 책을 모아 한 번에 사기 위해, 장바구니에 담고 수량을 바꾸고 싶다.
- 근거: REQ-015 · M3
- 정상 흐름
  1. 상세에서 담으면 "장바구니에 담았어요" 안내가 보이고 Header 장바구니 개수가 바뀐다.
  2. 장바구니에서 책별 수량 변경·빼기, 합계 금액을 본다.
  3. [주문하기]로 US-08로 간다.
- 거부 시나리오
  - REJ-12 재고보다 많은 수량: 재고 수까지만 담기고 "남은 책은 N권이에요" 안내.
  - REJ-13 담아 둔 책이 이후 품절: 장바구니에 품절 표시, 주문 대상에서 빠짐.
  - REJ-14 같은 책을 다시 담으면: 새 줄이 아니라 수량이 늘어난다.
- 관련 INV: INV-05

### US-08: 회원으로서, 책을 받기 위해, 배송지를 확인하고 카드나 간편결제로 주문하고 싶다.
- 근거: REQ-016, D-002, D-004, D-020 · M3
- 정상 흐름
  1. 주문서에 책 목록·합계, 기본 배송지(없으면 입력 칸)가 보인다. 입력한 배송지는 기본 배송지로 저장된다.
  2. [결제하기] → 결제 대행사 테스트 결제 창에서 카드·간편결제 → 확정되면 주문이 `paid`(주문 접수)가 되고 재고가 줄며 장바구니에서 빠진다.
  3. 주문 완료 화면에 주문 번호와 "책방지기가 곧 포장해 보내드려요" 안내.
  4. 주문에는 결제 시점 배송지 사본이 남는다(D-004).
- 거부 시나리오
  - REJ-15 결제 실패·창 닫기: 주문은 `pending_payment`, 장바구니 유지, "결제가 완료되지 않았어요" + [다시 결제하기].
  - REJ-16 결제 확정 시점에 재고 부족: 주문은 확정되지 않고 결제는 취소되며 품절 안내.
  - REJ-17 같은 결제 확정 신호가 두 번 와도: 주문 상태·재고는 한 번만 바뀐다.
  - REJ-18 배송지 필수 항목(받는 사람, 연락처, 주소) 누락: 결제 단계로 가지 않음.
  - REJ-56 결제 대행사가 승인한 금액이 주문 합계와 다르면: 주문을 확정하지 않고 결제를 취소하며 "결제 금액이 맞지 않아 결제를 취소했어요" 안내 (NFR-19).
- 관련 INV: INV-04, INV-05, INV-06

### US-09: 회원으로서, 책이 언제 오는지 알기 위해, 주문 현황을 보고 발송 전에는 취소를 요청하고 싶다.
- 근거: Q-004, Q-005 · M3
- 정상 흐름
  1. 마이페이지 주문 현황에 주문별 "주문 접수 → 발송됨" 2단계가 보인다.
  2. `paid` 주문에 [취소 요청]이 있고, 누르면 `cancel_requested` "취소 요청을 책방지기에게 전했어요"로 바뀐다.
  3. 취소 요청 중에는 [취소 요청 철회]가 있고, 누르면 `paid`로 돌아간다(D-029).
  4. 책방지기가 환불하면 "환불 완료", 거절하면 "책방지기가 취소 요청을 받지 않았어요. 책은 그대로 보내드려요"가 보이고 주문은 `paid`로 돌아간다.
- 거부 시나리오
  - REJ-19 `shipped` 주문은 [취소 요청]이 없다(발송 후 취소 불가 안내).
  - REJ-20 다른 회원의 주문 주소로 접근: 보이지 않음(없는 주문과 같은 안내).
  - REJ-58 책방지기가 이미 환불·거절한 요청을 철회하려 하면: 철회되지 않고 현재 상태를 안내한다.
- 관련 INV: INV-04, INV-20

### US-10: 책방지기로서, 주문을 처리하기 위해, 발송 대기 주문을 발송 처리하고 취소 요청을 환불하고 싶다.
- 근거: Q-004, Q-005, D-002 · M3
- 정상 흐름
  1. 관리자 주문 화면에 `paid`·`cancel_requested` 주문이 오래된 순으로 보인다(책, 수량, 배송지).
  2. 포장 후 [발송 완료]를 누르면 `shipped`.
  3. `cancel_requested` 주문의 [환불]을 누르면 결제 대행사 환불까지 처리되고 `refunded`, 재고가 돌아온다(D-002 A).
