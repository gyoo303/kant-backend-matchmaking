# 05. 사용자 스토리 & 기능 명세 (P5)

- 입력: `03-domain.md`(INV-01~15), `04-scope.md`(Must/Should/Could, M1~M7)
- 형식: 스토리 → 정상 흐름 → 거부 시나리오(`REJ-xx`) → 관련 INV
- 공통 거부(모든 로그인 필요 스토리에 적용): REJ-01 토큰 없음 / REJ-02 만료·위조 토큰 / REJ-03 블랙리스트 토큰 → 401 (REQ-010, REQ-060)
- 업무 단위(생성·참가·나가기·게임 시작) 중 하나라도 실패하면 모두 되돌린다(REQ-071, REQ-105). 필수 범위는 순차 요청 기준으로 INV를 지키고, 동시 요청 보장은 도전 A(US-18)에서 추가한다(D-018, NFR-04).

## M3 방 도메인 API

### US-01: 회원으로서, 함께할 사람을 모으기 위해, 제목만 입력해 방을 만들고 싶다.
- 근거: REQ-012, REQ-024~029, REQ-032, REQ-033, REQ-112, Q-03 · 마일스톤: M3
- 정상 흐름
  1. 회원이 제목을 입력해 방 생성을 요청한다.
  2. 서버가 제목을 다듬어(앞뒤 공백 제거) 검사하고, 회원이 현재 어떤 방에도 참가하지 않았는지 확인한다.
  3. 정원 4명 고정의 활성 방이 생기고, 생성자가 방장이 되며 A팀·입장 순서 1로 참가한다.
  4. 생성한 방의 상세 정보를 돌려받는다.
- 거부 시나리오
  - REJ-04 제목이 공백뿐이거나 앞뒤 공백 제거 후 0자·21자 이상 → 거부 (REQ-025)
  - REJ-05 이미 다른 방에 참가 중인 회원의 생성 요청 → 거부 (REQ-033)
  - REJ-06 정원·팀 등 제목 외 입력을 보내도 서버가 무시하고 고정 정원을 적용 (REQ-024)
- 관련 INV: INV-01, INV-04, INV-05, INV-12

### US-02: 회원으로서, 게임에 함께하기 위해, 빈자리가 있는 방에 참가하고 싶다.
- 근거: REQ-033~035, REQ-037, REQ-040, REQ-046, Q-03, D-006 · M3
- 정상 흐름
  1. 회원이 방 참가를 요청한다.
  2. 서버가 요청 시점의 삭제 상태·정원·회원의 현재 참가를 다시 검사한다.
  3. 다음 입장 순서로 참가 기록이 생기고, 인원이 적은 팀(같으면 A팀)에 배정된다.
  4. 같은 방에 이미 참가 중이면 기존 참가를 그대로 돌려준다(새 기록 없음).
  5. 나갔거나 해산된 뒤 다시 들어오면 새 기록·새 입장 순서를 받는다.
- 거부 시나리오
  - REJ-07 없는 방 → 404 (REQ-061)
  - REJ-08 삭제된 방 → 거부 (REQ-031)
  - REJ-09 정원 4명 마감 → 거부 (REQ-035)
  - REJ-10 다른 방에 참가 중 → 거부 (REQ-033)
- 관련 INV: INV-02, INV-03, INV-04, INV-06, INV-11

### US-03: 방장으로서, 방 성격을 알리기 위해, 방 제목을 바꾸고 싶다.
- 근거: REQ-013, REQ-025, REQ-030, REQ-031 · M3
- 정상 흐름: 방장이 새 제목을 보내면 규칙 검사 후 제목이 바뀌고, 다른 참가자 화면에는 다음 조회에서 반영된다.
- 거부 시나리오
  - REJ-11 현재 방장이 아닌 회원의 요청 → 거부 (REQ-030)
  - REJ-12 삭제된 방 → 거부 (REQ-031)
  - REJ-04 제목 규칙 위반 → 거부
  - REJ-07 없는 방 → 404
- 관련 INV: INV-05, INV-06, INV-12

### US-04: 참가자로서, 원하는 편에서 하기 위해, 내 팀을 바꾸고 싶다.
- 근거: REQ-014, REQ-036, REQ-113, Q-02 · M3
- 정상 흐름: 참가자가 대상 팀(A/B)을 보내면 대상 팀 인원이 2명 미만일 때 본인 팀이 바뀐다. 이미 그 팀이면 변경 없이 성공한다.
- 거부 시나리오
  - REJ-13 대상 팀이 2명으로 마감 → 거부 (REQ-036)
  - REJ-14 이 방의 현재 참가자가 아닌 회원 → 거부 (REQ-014)
  - REJ-12 삭제된 방 → 거부
  - REJ-15 A/B가 아닌 팀 값 → 422 (입력 형식)
- 관련 INV: INV-03, INV-06
- 참고: 다른 참가자의 팀을 바꾸는 기능은 없다(Q-02). 자리 교환 기능도 없다(REQ-036).

### US-05: 참가자로서, 방을 떠나기 위해, 나가기를 하고 싶다.
- 근거: REQ-041~045, REQ-070 · M3
- 정상 흐름
  1. 참가자가 나가기를 요청하면 본인 참가에 퇴장 시각이 기록된다.
  2. 일반 참가자면 방장은 그대로다.
  3. 방장이고 남은 참가자가 있으면 입장 순서가 가장 빠른 참가자가 새 방장이 된다.
  4. 마지막 참가자면 방이 소프트 삭제된다(사유: 참가자 없음). 이용 기록은 남는다.
- 거부 시나리오
  - REJ-16 이 방의 현재 참가자가 아닌 회원 → 거부 (REQ-041)
  - REJ-07 없는 방 → 404
- 관련 INV: INV-02, INV-05, INV-06, INV-07, INV-10

### US-06: 방장으로서, 모인 4명으로 게임을 시작하기 위해, 게임 시작을 누르고 싶다.
- 근거: REQ-015, REQ-048~052, REQ-114, Q-01 · M3
- 정상 흐름
  1. 방장이 게임 시작을 요청한다.
  2. 서버가 활성 방인지, 요청자가 현재 방장인지, A팀·B팀이 각각 정확히 2명인지 검사한다.
  3. 결과 판정 없이 방이 소프트 삭제되고(사유: 게임 시작), 4명 모두의 참가에 퇴장 시각이 기록된다.
  4. 4명 모두 새 방을 만들거나 참가할 수 있게 된다.
- 거부 시나리오
  - REJ-17 현재 방장이 아닌 회원 → 거부 (Q-01)
  - REJ-18 A·B가 각각 2명이 아님(인원 부족, 3:1 등) → 거부 (REQ-048)
  - REJ-19 이미 해산된 방(반복 요청) → 거부, 해산은 한 번만 (REQ-052, REQ-101)
  - REJ-07 없는 방 → 404
- 관련 INV: INV-06, INV-07, INV-08, INV-09
- 참고: 승패·게임 결과 데이터는 만들지 않는다(INV-09).

### US-07: 회원으로서, 방 상황을 알기 위해, 방 상세와 내가 참가 중인 방을 보고 싶다.
- 근거: REQ-011, REQ-075, REQ-077, REQ-094, REQ-116 · M3
- 정상 흐름
  1. 활성 방 상세에서 제목·현재 인원/정원(4)·방장·참가자 닉네임·현재 팀을 본다. 입장 순서는 보이지 않는다(REQ-045).
  2. 본인의 현재 참가 방(없으면 없음)을 조회한다. 로그아웃 후 다시 로그인해도 같다.
  3. 삭제된 방을 일반 상세로 조회하면, 게임 시작으로 해산된 방과 그 밖의 접근 불가를 구분할 수 있는 응답을 받는다(응답 계약은 ARCH-Q-04).
- 거부 시나리오
  - REJ-07 없는 방 → 404
  - REJ-20 삭제된 방의 과거 참가자 정보를 일반 상세로 노출하지 않음 (REQ-056)
- 관련 INV: INV-15

## M4 인증

### US-08: 방문자로서, 서비스를 쓰기 위해, 아이디·닉네임·비밀번호로 가입하고 싶다.
- 근거: REQ-020~022, REQ-115, Q-04, D-011 · M4
- 정상 흐름: 아이디·닉네임·비밀번호를 보내면 비밀번호는 해시로 저장되고, 응답에는 비밀번호·해시가 없다.
- 거부 시나리오
  - REJ-21 아이디 형식 위반(4~20자 영문 소문자·숫자 아님) → 거부
  - REJ-22 닉네임 형식 위반(공백 제거 후 2~12자 한글·영문·숫자 아님) → 거부
  - REJ-23 비밀번호 8자 미만 → 거부
  - REJ-24 이미 쓰는 아이디 또는 닉네임 → 거부
- 관련 INV: INV-13

### US-09: 회원으로서, 서비스를 쓰기 위해, 로그인해 토큰을 받고 싶다.
- 근거: REQ-020, REQ-T13 · M4
- 정상 흐름: OAuth2 로그인 양식으로 아이디·비밀번호를 보내면 JWT를 받는다. Swagger Authorize로도 로그인할 수 있다.
- 거부 시나리오: REJ-25 없는 아이디 또는 틀린 비밀번호 → 401 (어느 쪽이 틀렸는지 구분하지 않음)

### US-10: 회원으로서, 내 계정을 안전하게 하기 위해, 로그아웃하면 그 토큰이 더는 쓰이지 않게 하고 싶다.
- 근거: REQ-059, REQ-060, REQ-T14 · M4
- 정상 흐름: 로그아웃하면 현재 토큰이 블랙리스트에 등록된다. 참가 상태와 방장은 그대로다(REQ-038).
- 거부 시나리오: REJ-03 같은 토큰으로 다시 요청 → 401
- 관련 INV: INV-14

### US-11: 서비스로서, 회원만 쓰게 하기 위해, 로그인하지 않은 요청을 막고 싶다.
- 근거: REQ-010, D-005 · M4
- 정상 흐름: 회원가입·로그인 외 API는 토큰 없이 401, 화면은 로그인 화면으로 이동한다.
- 거부 시나리오: REJ-01~03

## M5 고도화·웹

### US-12: 회원으로서, 들어갈 방을 찾기 위해, 공개 방 목록을 검색·필터·정렬·페이지로 보고 싶다.
- 근거: REQ-079~085 · M5
- 정상 흐름
  1. 삭제되지 않은 방을 정원이 찬 방까지 포함해 보여 준다. 각 행: 제목, 현재 인원/정원, 생성 시각, 마감 여부.
  2. 제목 부분 검색(영문 대소문자 무시, 앞뒤 공백 제거, 비면 조건 없음, `%`·`_`는 문자 그대로).
  3. '빈자리 있는 방만 보기'를 켜면 정원이 찬 방을 뺀다.
  4. 정렬: 생성 시각 최신순(기본)·오래된순, 동률은 방 식별자.
  5. 페이지: 기본 1페이지·10건, 최대 50건. 응답에 조건을 적용한 전체 건수가 있다.
  6. 결과가 없거나 마지막 페이지를 넘으면 빈 목록이다.
- 거부 시나리오: REJ-26 페이지 0 이하, 페이지 크기 0 이하·50 초과, 정렬 값 오류 → 422 (REQ-062)

### US-13: 회원으로서, 내가 들어갔던 방을 돌아보기 위해, 내 이용 이력을 보고 싶다.
- 근거: REQ-017, REQ-053~056, REQ-117, D-007 · M5
- 정상 흐름: 본인 기록만 입장 시각 최신순(동률은 기록 식별자 내림차순), 기본 10건·최대 50건으로 본다. 각 기록: 방 제목, 입장 시각, 퇴장 시각 또는 '참가 중'. 재입장은 별도 기록이다.
- 거부 시나리오: REJ-26 잘못된 페이지 입력 → 422
- 관련 INV: INV-10, INV-15

### US-14: 과거 참가자로서, 사라진 방을 확인하기 위해, 삭제된 방의 보관 정보를 보고 싶다.
- 근거: REQ-016, REQ-057, REQ-058, REQ-118, D-009 · M5
- 정상 흐름: 내 기록에서 삭제된 방을 고르면 저장된 제목·정원·생성 시각·삭제 시각과 본인 이용 기록만 보인다. 다시 참가하거나 복구할 수 없다.
- 거부 시나리오: REJ-27 그 방에 참가한 적 없는 회원 → 404 (REQ-057)
- 관련 INV: INV-15

### US-15: 회원으로서, 로그인 직후 방을 고르기 위해, 공개 방 목록 화면(메인)을 쓰고 싶다.
- 근거: REQ-073, REQ-074, REQ-076, REQ-086~088, REQ-090, REQ-091, D-012 · M5
- 정상 흐름
  1. 로그인 후 첫 화면이 공개 방 목록이다. 상단에 현재 참가 중인 방 링크가 있다(없으면 숨김).
  2. 목록 위의 생성 폼에 제목만 입력하고, "2vs2, 4명 고정" 안내를 본다. 생성하면 방 상세로 이동한다.
  3. 정원이 찬 방은 '정원 마감' 표시와 비활성 참가 버튼을 보인다.
  4. 검색·필터·정렬을 바꾸면 1페이지부터, 페이지를 넘겨도 조건은 그대로다.
  5. 1초마다 목록을 다시 조회한다. 이전 조회가 끝나기 전엔 겹쳐 보내지 않고, 조건을 바꾸기 전 늦은 응답은 버린다. 탭을 숨기면 멈추고, 돌아오면 바로 조회 후 재개한다.
- 거부 시나리오: REJ-28 생성·참가 거부 시 화면이 멈추지 않고 거부 사유 문구를 보인다 (REQ-019)

### US-16: 참가자로서, 방 구성을 지켜보기 위해, 방 상세 화면(현황 대시보드)을 쓰고 싶다.
- 근거: REQ-089, REQ-092, REQ-095~097, D-012 · M5
- 정상 흐름
  1. 인원/정원과 A팀·B팀 구성(닉네임, 방장 표시)을 보여 주고 1초마다 갱신한다.
  2. 참가·나가기·팀 변경·제목 변경(방장)·게임 시작(방장) 버튼을 상태에 맞게 보인다. 본인 요청 성공은 바로 반영한다.
  3. 방장이 게임 시작에 성공하면 조회를 멈추고 공개 방 목록으로 이동한다. 다른 참가자는 다음 조회에서 해산을 확인하고 목록으로 이동한다.
  4. 게임 시작 전에 이미 나간 사람은 이동시키지 않는다.
- 거부 시나리오
  - REJ-29 통신 실패 → 마지막 정보 유지, "최신 정보를 불러오지 못했습니다" 표시, 다음 주기 재시도 (REQ-096)
  - REJ-30 인증 만료 → 폴링을 멈추고 로그인 화면으로 안내 (REQ-097)
  - REJ-31 해산이 아닌 접근 불가(없는 방 등) → 해산과 다른 안내 (REQ-094)

### US-17: 회원으로서, 가입·로그인하고 내 기록을 보기 위해, 회원가입·로그인·내 기록 화면(목록)을 쓰고 싶다.
- 근거: REQ-073, REQ-078, D-012 · M5
- 정상 흐름: 회원가입·로그인 화면은 제출 시 결과를 보인다. 내 기록 화면은 이용 이력 목록(US-13)과 페이지 이동, 삭제 방 보관 정보 보기(US-14)를 제공하며 수동 조회다.
- 거부 시나리오: REJ-32 빈 결과·통신 실패·인증 만료·접근 불가를 서로 다른 안내로 보인다 (REQ-078)

## M6 도전 (D-002, D-018 — 사용자 요청 시에만 착수)

### US-18 (Should, 도전 A): 팀으로서, 동시에 요청이 몰려도 규칙이 깨지지 않게 하기 위해, 동시 요청 무결성을 구현하고 재현 스크립트로 정원·한 방·팀 정원·해산 1회 규칙이 지켜짐을 보이고 싶다.
- 근거: REQ-098~104, REQ-107, REQ-T22, CH-A, D-018 · M6
- 정상 흐름: 방을 바꾸는 요청이 같은 방에서 차례로 처리되고, 한 회원의 현재 참가가 DB에서도 1건으로 막힌다. 스크립트가 같은 방 마지막 자리 동시 참가, 같은 회원의 동시 생성·참가, 같은 팀 동시 변경, 게임 시작 동시 반복을 보내고 결과를 출력한다.
- 거부 시나리오: 초과된 요청은 모두 거부되고 INV-02~08 위반이 0건이어야 한다.

### US-19 (Could, 도전 B): 팀으로서, 응답을 늦추지 않고 기록을 남기기 위해, 게임 시작 후 해산 로그를 백그라운드로 남기고, 회원은 본인 이용 이력을 CSV로 내려받고 싶다.
- 근거: REQ-T23, CH-B · M6
- 정상 흐름: 게임 시작 응답 뒤에 해산 로그가 남는다. CSV는 본인 기록만, 한 번에 메모리에 올리지 않고 내려준다.
- 거부 시나리오: REJ-01~03 비로그인 → 401

### US-20 (Could, 도전 C): 팀으로서, 반복 조회 부담을 줄이기 위해, 공개 방 목록에 캐시를 두고 변경 시 무효화하고, 환경변수로 실행 설정을 분리하고 싶다.
- 근거: REQ-T24, CH-C · M6
- 정상 흐름: 생성·참가·나가기·팀 변경·제목 변경·게임 시작 뒤에는 캐시가 무효화되어 다음 조회에 최신 상태가 보인다.
- 거부 시나리오: 캐시 때문에 삭제된 방이 목록에 남거나 마감 표시가 틀리면 안 된다.
