# 07. 화면 구성 & 와이어프레임 (P7)

- 입력: `05-user-stories.md`(US-18~23 등), `06-acceptance-criteria.md`(NFR-08~10)
- 화면은 서버 렌더링 페이지(Jinja2)와 Swagger UI뿐이다. 경로는 **후보**이며 Architect가 확정한다.
- 색·폰트 등 시각 디자인은 정하지 않는다. 구성 요소와 우선순위만 정한다.

## 2. 공통 요소 (기본 레이아웃 템플릿)

모든 페이지(SCR-01~08)가 같은 레이아웃을 쓴다.

| 요소 | 구성 | 상태별 표시 |

| 머리글 | 서비스 이름 '점프 5'(로비 링크), [매치 히스토리] 링크 | 비로그인: [로그인] [회원가입] / 회원: 닉네임, [로그아웃] / 운영자: 닉네임, [대시보드], [로그아웃] |

| 바닥글 | 서비스 이름, [API 문서(/docs)] 링크 | — |

## 3. 발제 핵심 3화면 와이어프레임

### SCR-01 로비 (메인)

```
┌ 머리글: 점프 5 | 매치 히스토리 |        용감한고양이42 [로그아웃] ┐
│ (안내 영역)                                                      │
│                                                                  │
│  모드를 골라 대기열에 들어가세요                                  │  ← REQ-038
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐              │
│  │  3 vs 3      │ │  5 vs 5      │ │  10 vs 10    │              │
│  │  대기 4 / 6  │ │  대기 0 / 10 │ │  대기 12 / 20│  ← 2초 갱신  │  ← REQ-045, NFR-08
│  │  [참가하기]  │ │  [참가하기]  │ │  [참가하기]  │              │  ← US-04
│  └──────────────┘ └──────────────┘ └──────────────┘              │
│                                                                  │
└ 바닥글: 점프 5 | API 문서 ─────────────────────────────────────────┘
```
- 필수 표시 요소: 모드 3개, 모드별 대기 인원/정원(실제 DB 값), 모드별 [참가하기], 로그인 회원 닉네임
- 상태별 표시
  - 비로그인: 대기 인원은 보이고, [참가하기]를 누르면 로그인 화면으로 이동 (AC-18-1)
  - 이미 대기 중인 회원: 대기 화면으로 이동 / 게임 중인 회원: 게임 화면으로 이동
  - 등록 거부(400): 안내 영역에 `detail` 문구, 화면 유지
- 좁은 화면(360px): 모드 카드를 세로로 쌓음 (NFR-09)

### SCR-07 매치 히스토리 (목록)

```
┌ 머리글 ───────────────────────────────────────────────────────────┐
│ 매치 히스토리                                                      │  ← REQ-043
│ 모드 [전체 ▼]  상태 [전체 ▼]  닉네임 [________] [검색]  정렬 [기본 ▼] │  ← US-12
│ ┌──────┬────────┬────────┬──────────────────────┬────────┬───────┐ │
│ │ 모드 │ 상태   │ 승리 팀│ 참가자               │ 시작   │ 소요  │ │
│ ├──────┼────────┼────────┼──────────────────────┼────────┼───────┤ │
│ │ 3v3  │ 게임 중│ —      │ 고양이42, 봇07, …    │ 14:02  │ 0:41  │ │  ← 게임 중이 먼저
│ │ 5v5  │ 종료   │ A팀    │ 여우11, 봇03, …      │ 13:50  │ 1:12  │ │
│ │ 3v3  │ 종료   │ 승자없음│ …                   │ 13:40  │ 3:05  │ │  ← 강제 종료
│ └──────┴────────┴────────┴──────────────────────┴────────┴───────┘ │
│  ◀ 이전   1 2 3   다음 ▶     (전체 25건, 쪽당 20건)                │  ← D-006
└ 바닥글 ───────────────────────────────────────────────────────────┘
행 클릭 → 게임 중이면 SCR-05(참가자) 또는 상세, 종료면 SCR-06
```
- 필수 표시 요소: 모드, 상태, 승리 팀(강제 종료는 "승자 없음"), 참가자 닉네임, 시작 시각, 소요 시간, 필터·검색·정렬·쪽 이동, 전체 건수
- 상태별 표시
  - 결과 없음: 표 대신 "아직 매치가 없습니다" (AC-23-2)
  - 잘못된 필터 값(422): 안내 영역 문구, 기본 조건으로 다시 표시
- 좁은 화면: 참가자 열을 줄이고 표는 세로 카드로 바꿈 (NFR-09)

### SCR-08 운영자 대시보드 (현황 대시보드)

```
┌ 머리글: … 운영자 [대시보드] [로그아웃] ─────────────────────────────┐
│ 대기열 현황 (2초 갱신)                                              │  ← US-16, NFR-08
│ ┌──────────┬──────────────┬──────────────────────────────────────┐ │
│ │ 모드     │ 대기 / 정원  │ 봇 투입                              │ │
│ │ 3 vs 3   │ 4 / 6        │ 인원 [2 ▼] [투입]                    │ │  ← US-14
│ │ 5 vs 5   │ 0 / 10       │ 인원 [  ▼] [투입]                    │ │
│ │ 10 vs 10 │ 12 / 20      │ 인원 [  ▼] [투입]                    │ │
│ └──────────┴──────────────┴──────────────────────────────────────┘ │
│ 진행 중 매치 (2초 갱신)                                             │
│ ┌──────┬──────┬───────────────┬───────────────┬──────┬──────────┐ │
│ │ 매치 │ 모드 │ A팀 점프 합계 │ B팀 점프 합계 │ 경과 │          │ │
│ │ #31  │ 3v3  │ 9             │ 7             │ 0:41 │ [강제 종료]│ │  ← US-10
│ └──────┴──────┴───────────────┴───────────────┴──────┴──────────┘ │
│ 이벤트 로그 (최근 순)                                               │  ← US-15
│ 14:02:11  매치 확정   3v3  #31                                     │
│ 14:01:58  등록        고양이42  3v3                                │
│ …                                                                  │
│ [매치 히스토리 CSV] [이벤트 로그 CSV]   (도전 B 채택 시)            │  ← US-26
└ 바닥글 ───────────────────────────────────────────────────────────┘
```
- 필수 표시 요소: 모드별 대기 인원/정원(실제 DB 값), 모드별 봇 투입, 진행 중 매치와 팀별 점프 합계·경과 시간, [강제 종료], 이벤트 로그
- 상태별 표시
  - 운영자가 아님: 접근 거부 안내 (AC-16-3)
  - 진행 중 매치 없음: "진행 중인 게임이 없습니다"
  - 봇 투입 거부(400/422): 안내 영역에 `detail` 문구
  - [강제 종료] 누름: 확인 문구 뒤 실행, 행이 목록에서 사라짐

## 4. 그 밖의 화면 (구성 요소·상태)

| SCR | 구성 요소 | 상태별 표시 |
|---|---|---|
| SCR-02 회원가입 | 닉네임 칸(추천 닉네임이 채워져 있고 고칠 수 있음), 비밀번호 칸, [가입] | 규칙 위반(REJ-07~09)은 해당 칸 옆 문구 / 성공 시 로그인 화면으로 |
| SCR-03 로그인 | 닉네임, 비밀번호, [로그인], 회원가입 링크 | 실패(REJ-10)는 "닉네임 또는 비밀번호가 맞지 않습니다" / 성공 시 로비, 게임 중이면 게임 화면 (도전 D: US-30) |
| SCR-04 대기 | 모드, 대기 현황(4/6), 경과 시간, [매칭 취소] | 2초 갱신 / 정원 충족 시 게임 화면으로 / 취소 시 로비로 / 이미 확정 뒤 취소(REJ-12)면 안내 후 게임 화면 |
| SCR-05 게임 | 내 팀, 내 점프 수(크게), 팀별 점프 합계, 참가자별 점프 수, 하단 대형 [점프] 버튼(모바일), 스페이스바 안내 | 2초 갱신 / 종료되면 결과 화면으로 / 참가자가 아니면 SCR-07로 안내 |
| SCR-06 결과 | 개인 승리 여부, 팀 승리 여부, 승자 닉네임, 팀별 최종 점프 수, 소요 시간, [로비로] | 강제 종료면 "승자 없음" |
| SCR-09 API 문서 | Swagger UI, [Authorize]로 로그인 | — |

## 5. 화면 이동

```
SCR-01 로비 ──[참가하기]──▶ SCR-04 대기 ──(정원 충족)──▶ SCR-05 게임 ──(종료)──▶ SCR-06 결과 ──[로비로]──▶ SCR-01
    │  ▲                         │
    │  └────────[매칭 취소]──────┘
    ├─(비로그인)──▶ SCR-03 로그인 ◀──▶ SCR-02 회원가입
    ├──▶ SCR-07 히스토리
    └─(운영자)──▶ SCR-08 대시보드
```

## 6. 시연 흐름 초안 (EV-10, 5분)

발제 시연 순서(REQ-T27)를 따른다. 사람은 운영자 1명 + 플레이어 1명(휴대폰)으로 가정한다.

| 순서 | 시간 | 화면 | 보여 줄 것 | 근거 |
|---|---|---|---|---|
| 1 | 0:00~0:40 | SCR-01, SCR-07 | 로비의 모드별 대기 인원, 히스토리 목록(시드 데이터), 필터·쪽 이동 | EV-08, AC-11-1 |
| 2 | 0:40~1:20 | SCR-02, SCR-03 | 휴대폰으로 가입(추천 닉네임) → 로그인 | AC-01-1, AC-02-1 |
| 3 | 1:20~2:40 | SCR-04 → SCR-05 → SCR-06, SCR-08 | 플레이어가 3 vs 3 등록(200) → 대시보드에서 봇 5명 투입 → 매치 확정 → 하단 [점프] 버튼으로 게임 → 결과 화면 | AC-04-1, AC-14-1, AC-08-2 |
| 4 | 2:40~3:40 | SCR-09 | Swagger: 정상 등록 200 → 같은 회원 중복 등록 400 → 없는 매치 404 → 남의 티켓 취소 400 | AC-04-2, AC-09-4, AC-05-2 |
| 5 | 3:40~4:30 | SCR-09 | Swagger Authorize 로그인 → 로그아웃 → 같은 토큰으로 요청 401 | AC-03-2 |
| 6 | 4:30~5:00 | SCR-08, 콘솔 | 이벤트 로그와 요청 로그(처리 시간), (도전 A 채택 시) 동시 등록 스크립트 결과 | AC-15-1, NFR-11, AC-24-1 |
