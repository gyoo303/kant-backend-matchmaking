# ADR-006: 동시성 제어 (필수 무결성 + 도전 A)
- 상태: Superseded by ADR-009
- 관련 계층: [모듈 협력 구조] [인프라]
- 근거: D-002, DRV-C-07, RISK-03~05, ARCH-Q-02, INV-02~08, REQ-098~104, NFR-04, AC-18-*, CH-A

## 맥락
D-002로 동시 요청 무결성은 필수다. 도메인 검사만으로는 두 요청이 같은 상태를 동시에 읽으면 정원·팀 정원·해산 1회가 깨진다. 한 회원 한 방은 여러 방에 걸친 규칙이라 방 하나의 잠금으로 막을 수 없다.

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향(D2~D4) | 평가표 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. 방을 바꾸는 모든 요청(참가·제목·팀 변경·나가기·게임 시작)은 `rooms` 행을 `SELECT … FOR UPDATE`로 잠근 뒤 참가자를 읽고 도메인 메서드 실행. 한 회원 한 방은 `participations(user_id) WHERE left_at IS NULL` 부분 유니크 인덱스로 막고 `IntegrityError`를 400으로 변환 | 같은 방 요청이 직렬화되어 도메인 검사가 그대로 유효, 구현 단순 | 같은 방 요청은 차례로 처리(시연 규모에서 무시 가능) | 낮음 — 규칙은 도메인, 직렬화는 레포지토리 한 메서드 | 충족 | 중 |
| B. `rooms.version` 낙관적 잠금, 충돌 시 409 후 재시도 | 잠금 대기 없음 | 재시도 규칙·409 코드 추가, 4명 방에서는 충돌이 잦음 | 중 | 충족 | 중 |
| C. DB 제약만(CHECK·카운터 컬럼) | 코드 적음 | 팀 정원·해산 1회·위임 대상은 제약으로 표현 불가 | 높음 | 위험 | 높음 |

## 계층 관점 설명
[모듈 협력 구조] `RoomRepository.find_by_id_for_update(room_id)`가 방 행을 잠그고 현재 참가자를 함께 로딩한다. 서비스는 잠금 → 도메인 메서드 → `save` → `commit` 순서만 지킨다. 방 생성은 잠글 방이 없으므로 부분 유니크 인덱스가 마지막 방어선이다. [인프라] 커넥션 풀 `pool_size=10`, `max_overflow=10`(ADR-003 환경변수).
- 도전 A 재현: `tests/concurrency/test_room_concurrency.py`가 실제 DB에 `asyncio.gather`로 AC-18-1~5 요청을 동시에 보내고 결과 건수를 단언한다.

## 결정 / 추천
결정: A — 도메인 규칙은 그대로 두고, 레포지토리 잠금 한 곳과 인덱스 하나로 RISK-03~05를 막는다.

## 결과
- 감수할 점: 잠금 없는 조회로 변경하면 무결성이 깨짐 → CONV-08, GATE-07로 검사
- 후속 작업: TKT-DB-02, TKT-BE-M3-02~04, TKT-QA-M6-01
