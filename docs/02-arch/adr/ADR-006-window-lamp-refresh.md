# ADR-006: 창가 등불 상태를 회원 화면에 반영하는 방식
- 상태: Accepted (user, 2026-10-21)
- 관련 계층: [모듈 협력 구조] [인프라]
- 근거: NFR-17, AC-12-6, REQ-036, DRV-Q-04, →ARCH A-04, UX-CTX-ORCH §3("의도된 느림"을 정보 숨김으로 만들지 않음)

## 맥락
책방지기가 편지를 열면 회원 창가가 촛불로 바뀐다. NFR-17은 "진입·새로고침 시 최신"만 요구한다. 시연(SCR-19 + SCR-15 두 창)에서 바로 바뀌는 모습이 필요한지가 쟁점이다.

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향(D2~D4) | KANT 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. 화면 진입 시 조회(캐시 없음) | 구성 요소 0개 추가, NFR-17 그대로 충족 | 시연 때 회원 창에서 새로고침 필요 | 낮음 | 없음 | 낮음 |
| B. A + 창가 화면에서 30초 폴링(`router.refresh()`) | 시연에서 자동 반영, 서버 변경 없음 | 화면이 열려 있는 동안 주기적 요청 | 낮음 | 없음 | 낮음 |
| C. Supabase Realtime(`postgres_changes`) 구독 | 즉시 반영 | 연결 관리, Realtime의 RLS 설정, 블라인드 컬럼 노출 주의(RISK-08) | 중 | 없음 | 중 |

## 계층 관점 설명
- [모듈 협력 구조] A·B는 상태의 원천이 DB 조회 하나. C는 DB 변경 이벤트가 브라우저로 직접 흘러, 회원에게 가는 행에 블라인드 대상 컬럼이 섞이지 않도록 별도 공개용 테이블/뷰가 필요하다.

## 결정
선택 **A** — 의뢰서의 "의도된 느림"과 맞고 NFR-17을 그대로 충족한다. 시연은 "회원 창 새로고침" 한 동작으로 보여 준다. 자동 반영이 꼭 필요하면 B(코드 10줄 내외)로 올린다.

## 결과
- 좋아지는 점: 추가 인프라 0, 블라인드 노출 경로 0
- 감수할 점: 실시간감 없음
- 후속: TKT-FE-M4 창가 화면은 `<Suspense>` 안에서 요청 시점 조회(CONV-07)
