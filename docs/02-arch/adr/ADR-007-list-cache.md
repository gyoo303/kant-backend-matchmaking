# ADR-007: 공개 방 목록 캐시 (도전 C, Could)
- 상태: Accepted (user, 2026-10-28)
- 관련 계층: [모듈 협력 구조]
- 근거: D-002, D-018, US-20, AC-20-1·2, NFR-08, CH-C

## 맥락
공개 방 목록은 회원마다 화면 진입·[새로고침]·조건 변경 때 조회한다(ADR-012). 도전 C는 캐시와 무효화를 요구한다. 캐시 때문에 해산된 방이 남거나 인원이 틀리면 안 된다(AC-20-1·2).

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향(D2~D4) | 평가표 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. 직접 구현: `rooms/application/list_cache.py`의 프로세스 내 dict, 키 = 정규화된 쿼리 조건, TTL 5초, 방을 바꾸는 서비스 메서드가 `commit` 직후 `clear()` | 의존성 0, 무효화 위치가 서비스 하나 | 워커 1개에서만 일관(ADR-008) | 낮음 | 충족 | 낮음 |
| B. `cachetools.TTLCache` 라이브러리 | 검증된 구현 | 의존성 추가, 동작은 A와 같음 | 낮음 | 충족 | 낮음 |

## 계층 관점 설명
[모듈 협력 구조] `RoomQueryService.list_rooms()`만 캐시를 읽는다. `RoomApplicationService`의 생성·참가·제목·팀·나가기·게임 시작 메서드는 `commit` 성공 후에만 `clear()`한다(실패 시 무효화 없음). 상세·이력 조회는 캐시하지 않는다.

## 결정 / 추천
결정: A — 의존성 없이 같은 동작을 만들고 무효화 규칙이 한 파일에 있다.
