# ADR-007: 주소록 파일 형식과 다운로드 기록
- 상태: Accepted (user, 2026-10-21)
- 관련 계층: [인프라] [모듈 협력 구조]
- 근거: REQ-055, AC-19-1~4, INV-17, NFR-09, RISK-09, →ARCH A-06·A-11

## 맥락
AC-19-1은 "엑셀에서 바로 열리고 한글이 깨지지 않는 파일"을 요구한다. 주소록은 개인정보 묶음이라 누가 언제 받았는지 남길지도 함께 정한다.

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향(D2~D4) | KANT 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. CSV(UTF-8 BOM, CRLF) + 다운로드 기록 테이블 | 의존성 0, Excel에서 한글 정상 | 서식(열 너비) 없음 | 낮음 | 없음 | 낮음 |
| B. xlsx(`exceljs` 추가) + 다운로드 기록 | 진짜 엑셀 파일, 서식 가능 | 패키지 1개(약 1MB) 추가 | 중: 의존성 증가 | 없음 | 낮음 |
| C. CSV, 기록 없음 | 가장 작음 | 유출 시 추적 불가 | 중: RISK-09 미대응 | 없음 | 낮음 |

## 계층 관점 설명
- [인프라] 파일은 서버(`app/api/admin/shipping-list/route.ts`)에서 매 요청 생성해 바로 응답한다. Storage에 저장하지 않는다(사본이 남지 않음).
- [모듈 협력 구조] 조회 → CSV 생성(`domains/shipping/shipping-list.ts` 순수 함수) → `shipping_list_downloads`에 1행 기록 → 응답. 0건이면 파일 대신 안내(AC-19-2).

## 결정
선택 **A** — AC-19-1을 의존성 없이 충족하고, 기록 1행으로 RISK-09에 대응한다. SCR-13 버튼 아래에 "내려받은 파일은 발송 후 지워 주세요" 안내 문구를 둔다(A-11).

## 결과
- 좋아지는 점: 패키지 추가 0, 다운로드 추적 가능
- 감수할 점: 열 너비 등 서식 없음
- 후속: TKT-DB-02(`shipping_list_downloads`), TKT-BE-M4-04
