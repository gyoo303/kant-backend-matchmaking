# ADR-008: 외부 입력 런타임 검증 방식
- 상태: Accepted (user, 2026-10-21)
- 관련 계층: [레이어]
- 근거: DRV-Q-01·02, RISK-02, AC-06-4, AC-11-5, AC-16-5, AC-17-4, AC-18-5, D-025, 스킬 §A4(`any` 금지·런타임 검증)

## 맥락
폼(책 등록, 배송지, 편지, 메모, 작별 안부, 힌트), URL 파라미터(`theme`, `id`), PG 응답·웹훅을 받는다. 같은 규칙(글자 수, 정수, 6자리)을 화면과 서버가 함께 써야 한다.

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향(D2~D4) | KANT 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. 손으로 쓴 검증 함수(`domains/*/…validate.ts`, 결과 `{ ok, errors }`) | 의존성 0, 규칙이 짧음(필드 20개 내외) | 타입과 검증이 따로 놀 수 있음 | 중: 타입 불일치 위험 | 없음 | 낮음 |
| B. `zod` 4.x 추가, 스키마에서 타입 추론(`z.infer`) | 타입·검증 한 곳, 오류 메시지 구조화 | 패키지 1개 추가 | 낮음 | 없음 | 낮음 |

## 계층 관점 설명
- [레이어] 검증 스키마는 `domains/<d>/<d>.schema.ts`(순수, 화면·서버 공용)에 두고, Server Action·Route Handler 첫 줄에서 `safeParse`한다. 실패하면 `ActionResult`의 `fieldErrors`로 돌려준다(04 §에러 모델).

## 결정
선택 **B** — 타입과 검증을 한 정의로 묶어 `as` 단언 없이 외부 입력을 다룬다. 같은 일을 하는 다른 라이브러리는 두지 않는다.

## 결과
- 좋아지는 점: 금지 패턴(타입 우회) 필요 지점 0
- 감수할 점: `zod` 의존성 1개
- 후속: TKT-BE-00(스키마 공용 모듈)
