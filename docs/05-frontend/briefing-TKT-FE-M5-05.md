### 구현 중 자율 결정

#### 스크립트를 템플릿 안에 둠
- 결정: 두 화면의 JS는 각 템플릿의 `scripts` 블록 안에 둔다 — HANDOFF TKT-FE-M5-05 산출에 JS 파일이 없음, M5-01 브리핑 "화면 공통 도우미를 api.js에 둠"
- 선택지: **A. 템플릿 안 스크립트 (권장·채택)** / B. `history.js` 새 파일
- 권장 이유: 산출 목록 밖 파일을 만들지 않고, 화면이 단순(한 번 조회)해 짧다. 회원가입·로그인 화면과 같은 방식이다.
- trade-off: A — 템플릿과 JS가 한 파일에 섞인다. B — 역할 분리는 깔끔하지만 산출 밖 파일이 생긴다.

#### 보관 정보 404 문구는 화면 명세를 따름
- 결정: API 문구("방을 찾을 수 없습니다") 대신 화면 명세 문구 "찾을 수 없습니다"를 보인다 — `07-screens.md` §4 SCR-06, PAGE-06
- 선택지: **A. 화면 명세 문구 (권장·채택)** / B. API `detail` 그대로
- 권장 이유: PM 화면 명세와 ARCH 화면 데이터 계약이 모두 "찾을 수 없습니다"로 적었다.
- trade-off: A — API 문구와 한 글자 다르다. B — 화면 명세와 어긋난다.

#### 기록 화면은 폴링하지 않음
- 결정: 화면을 열 때 한 번만 조회한다 — SCR-05·06 명세와 AC-17에 실시간 갱신 요구 없음(1초 폴링은 SCR-03·04만, SEQ-13)
- 선택지: **A. 한 번 조회 (권장·채택)** / B. 1초 폴링
- 권장 이유: 지난 기록은 자주 바뀌지 않고 요청 수를 늘릴 이유가 없다.
- trade-off: A — 다른 탭에서 나간 기록은 새로고침해야 보인다. B — 필요 없는 요청이 생긴다.

#### 잘못된 page 값은 1페이지로
- 결정: `data-page`가 숫자가 아니거나 0이면 1페이지를 부른다 — PAGE-05 `page: int`
- 선택지: **A. 1로 대체 (권장·채택)** / B. 그대로 보내 422 문구 표시
- 권장 이유: 주소를 손으로 바꾼 경우에도 빈 화면 대신 기록을 보여 준다.
- trade-off: A — 주소의 `page=0`과 실제 페이지가 다르다. B — 사용자에게 검증 문구만 보인다.
