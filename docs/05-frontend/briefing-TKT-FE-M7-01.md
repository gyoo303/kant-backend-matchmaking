### 구현 중 자율 결정

#### 구조도는 실제 파일 기준으로 그림
- 결정: 트리를 `05-structure-conventions.md` §1 원본이 아니라 지금 저장소에 있는 파일로 그렸다 — 원본에는 도전 과제 파일(`list_cache.py`, `tests/concurrency/`)과 만들지 않은 조각(`room_row.html`, `history_row.html`)이 있다
- 선택지: **A. 실제 파일 (권장·채택)** / B. 설계 원본 그대로
- 권장 이유: README는 제3자가 저장소를 보고 따라가는 문서라 없는 파일이 있으면 혼란스럽다(평가 10 "문서만 보고 실행").
- trade-off: A — 도전 과제를 진행하면 README 트리를 고쳐야 한다. B — 설계 문서와 같지만 실제와 어긋난다.

#### 요청 흐름의 로깅 미들웨어 이름
- 결정: 흐름도의 `RequestLoggingMiddleware`를 실제 함수 이름 `log_requests`로 썼다 — `src/logging_middleware.py`, `src/main.py`(등록 순서상 CORS가 바깥)
- 선택지: **A. 실제 이름 (권장·채택)** / B. 설계 이름
- 권장 이유: 코드에서 바로 찾을 수 있다.
- trade-off: A — 설계 문서 §4와 이름이 다르다. B — 코드에 없는 이름이다.

#### 시연 계정 절에 시드 방 표와 다중 브라우저 안내 추가
- 결정: 목차 4의 계정 안내에 `src/seed.py`의 방 구성 표와 "여러 회원 시연은 다른 브라우저·시크릿 창" 안내를 붙였다 — 토큰이 `localStorage`라 같은 브라우저 탭은 로그인을 공유(D-021), 시연 흐름 2단계(`07-screens.md` §5)
- 선택지: **A. 추가 (권장·채택)** / B. 계정·비밀번호만
- 권장 이유: 시연 2·5단계(4명 참가·게임 시작)를 준비할 때 어느 계정이 어느 방에 있는지 바로 알 수 있다.
- trade-off: A — 시드가 바뀌면 표도 고쳐야 한다. B — 짧지만 시연 준비 때 코드를 열어 봐야 한다.

#### 도전 C 절은 명령만 남기고 미진행 표시
- 결정: 목차 5 "시연 실행(도전 C 채택 시)"는 ADR-008의 명령을 적고 "도전 C는 아직 진행하지 않았다"고 표시했다 — HANDOFF §2, ADR-008, D-018
- 선택지: **A. 명령 + 미진행 표시 (권장·채택)** / B. 절 생략
- 권장 이유: 목차 항목을 모두 채우면서 진행 상태를 숨기지 않는다.
- trade-off: A — 아직 쓰지 않는 명령이 보인다. B — 목차와 어긋난다.
