database.py는 두 번째 import 때 다시 실행되지 않아요. 파이썬은 모듈을 한 번만 실행해요.

왜 main.py가 모델 모듈을 굳이 import할까?
create_all은 등록된 것만 만들어요. import를 빠뜨리면 오류 없이 테이블만 빠진 채 앱이 떠요. 그래서 # noqa: F401을 붙여 남겨요.

1. import 구간 · 1-3 ~ 1-4

나머지 import, 그리고 app 만들기

  • 라우터: router·page_router B C E
  • config, database, exceptions, logging_middleware A
  • from seed import seed_initial_data A → 안에서 다시 import:
    B User, UserRepository, PasswordHasher
    C Room
    D RoomRepository
  • app = FastAPI(..., lifespan=lifespan) → lifespan은 등록만, 실행은 아직

B·C·D 중 하나라도 비어 있으면 import 단계에서 앱이 멈춰요. 그래서 seed.py는 가장 마지막에 해요.
여기까지 DB에는 아무 일도 일어나지 않았어요.

2. 시작 구간

uvicorn이 서버를 열기 직전에 lifespan을 실행해요

@asynccontextmanager
async def lifespan(_: FastAPI):
    async with engine.begin() as conn:                         # 2-1 첫 DB 접속
        await conn.run_sync(Base.metadata.create_all)           # 2-2 CREATE TABLE
    async with AsyncSessionLocal() as session:                  # 2-3 시드용 세션
        await seed_initial_data(session, get_settings())        # 2-4 시드 INSERT
        await session.commit()                                  # 2-5 한 번에 확정
    yield                                                       # 2-6 요청 받기 시작
    await engine.dispose()                                      # 3   종료 정리
2-1 · 2-2

첫 접속 → create_all이 FK 순서대로 테이블을 만들어요

  • 2-1 engine.begin(): 풀에서 연결을 열고 트랜잭션 시작. DB가 꺼져 있거나 .env가 틀리면 여기서 처음 실패
  • 2-2: create_all은 동기 함수 → 비동기 연결 위에서 run_sync로 실행 (교안 5장)
users→token_blacklist→rooms→ users→teams→ rooms→participations→ rooms·users·teams→participation_logs
  • 테이블마다 있으면 건너뛰고, 없으면 CREATE TABLE
  • async with가 끝나면 commit → 테이블은 이 시점에 확정

이미 있는 테이블의 컬럼·PK는 고치지 않아요(STK-13). 모델을 바꾸면 개발 DB를 다시 만들어요.

시드는 ORM 모델을 직접 만들지 않아요. 도메인 규칙을 거치고, 로그 이동은 D의 save가 맡아요(ADR-011).

RoomRepository.save · 참가 분기

현재 참가는 participations, 끝난 참가는 participation_logs

도메인 room.participations하나씩 확인
⇉
left_at 없음 = 현재 참가 model.participations.append(ParticipationModel(...)) → INSERT participations (활성 방)
left_at 있음 = 끝난 참가 session.add(ParticipationLogModel(room=model, team=…, left_at=…)) → INSERT participation_logs (삭제 방)

flush 때 SQLAlchemy가 FK 순서로 INSERT해요: rooms → teams 2행 → participations 또는 participation_logs

삭제된 방은 참가가 전부 끝난 상태라 participations 행이 하나도 안 생기고 바로 로그로 가요.
