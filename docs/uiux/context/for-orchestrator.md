# [UI/UX → ① PM·Architect] 도메인 지식 컨텍스트 (UX-CTX-ORCH)
- 버전: v0.1 / 기반: UX-KNOW v0.1, PM 문서 d32207e(재작성본) / 승인: 조성아 (2026-10-21)
- 인용 번호는 **최신 PM 문서(d32207e) 기준**이다. UX-KNOW v0.1 안의 PM 번호는 이전 PM 문서 기준이라 일부 다르다(v0.2에서 고칠 예정). 둘이 다르면 이 팩을 따른다.
- 읽는 법: 우분투북스 고유 사실은 의뢰서 REQ만 근거다. 기초 문서(UX-BASE)는 **다른 독립서점 4곳을 손님으로 방문한 조성아 1인의 경험**(2020-04~2022-03)이라, "독립서점 손님이 무엇을 보고 느끼는가"의 근거로만 쓴다. 근거 강도 `강함`인 항목은 아직 없다.

## 1. 서점 정체성 (요약)
- 대전 어은동 골목의 작은 책방. 자연·식문화·생태·로컬 4개 테마로 책을 소개한다. [근거: REQ-001, REQ-010]
- 빠른 쇼핑몰이 아니라 "의도된 느림"과 손편지의 온기로 독자와 천천히 관계를 맺는 곳이다. [근거: REQ-002, REQ-003, REQ-004]
- 독립서점 손님에게는 **공간의 분위기와 책이 놓인 방식**이 서점의 인상을 만든다. [근거: exp-001 §2·§4, exp-002 §2·§4] (강도: 보통)
- 운영자 개인의 목소리(직접 쓴 책 이야기)가 서점 경험의 일부였다. 의뢰서의 "책방지기 노트 최상단" 요구(REQ-012, INV-02)와 같은 방향이다. [근거: exp-002 §3] (강도: 보통)

## 3. 기능 우선순위와 정보 구조에 대한 의견
- **SCR-01 메인의 "소개 → 테마 → 추천 책" 순서에 동의한다.** 손님이 먼저 공간의 결을 느끼고(G1), 그다음 테마로 고르게 된다(G2). [근거: exp-001 §4, exp-002 §2] (강도: 보통)
- **Header 메뉴 이름(테마 서가, 편지 구독)은 PM 용어집과 같아서 그대로 쓴다.** 별도의 "책방 소개" 페이지는 없고, 메인 소개 문구가 그 역할을 한다(PM-SCR §3).
- **기다림 화면(SCR-15 창가, SCR-16 언박싱)에는 늘 "지금 단계" 문구가 보여야 한다.** PM-DOMAIN §5.3의 상태 문구가 이미 이 역할을 한다. 기다림 연출을 이유로 상태 문구를 빼지 않도록 유지해 달라. [제안] [근거: exp-001 §2·§4] (강도: 약함)
- 범위에 영향이 있어 UX가 정하지 않는 질문은 §6에 모았다.

## 4. 용어
- 기능 용어는 **PM-DOMAIN §3 용어집을 그대로 쓴다.** UX 문서도 같은 용어와 식별자를 쓴다.
- 기초 문서의 "운영자"는 다른 서점의 운영자다. 우분투북스에서는 "책방지기"(`Keeper`)로 부른다.
- 기초 문서의 "큐레이션"(책을 고르고 소개하는 방식)은 우분투북스 화면에서 테마(`Theme`)와 책방지기 노트(`keeperNote`)로 드러난다. 화면 문구에 "큐레이션"이라는 말을 따로 쓸 필요는 없다. [제안]

## 5. 하지 말아야 할 것
- 의뢰서가 금지한 것은 PM의 Won't와 INV를 따른다: 당일 배송·실시간 택배 추적 등 빠른 쇼핑 지향(REQ-003), QR 스캔(INV-10), 별점·공개 리뷰·독서 토론(INV-11), 해지 방어 단계(INV-13).
- 할인율·판매 순위처럼 판매 정보만 앞세우는 화면 구성은 피한다. [근거: REQ-003, overview §3-3] (기초 문서 쪽은 생각, 약함)
- 기초 문서의 `(웹 확인)` 정보(다른 서점의 현재 SNS·운영 방식)를 우분투북스 사실처럼 쓰지 않는다. [근거: overview §4]
- "의도된 느림"을 정보를 숨기는 것으로 만들지 않는다. [근거: exp-001 §2·§4, REQ-004] (약함)
