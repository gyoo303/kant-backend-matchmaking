## 수정요청

### R-01 [불편] "편지 구독"이라는 같은 이름이 서로 다른 화면으로 간다
- 위치: PM-SCR §2 Header("편지 구독 → `/letters/new`"), SCR-06 마이페이지 메뉴("편지 구독"), SCR-15 화면 이름 "창가(편지 구독)", US-05 정상 흐름 3("편지 구독·창가(US-12)")
- 관련 번호: US-05, US-11, US-12 / G4
- 문제: Header의 "편지 구독"은 편지지(SCR-14)로, 마이페이지의 "편지 구독"은 창가(SCR-15)로 간다. 진행 중 회차가 있는 회원이 Header를 누르면 편지지 대신 안내 문구(REJ-24)만 보게 된다. 같은 행동 이름도 "편지 띄우기"(SCR-06, REJ-28), "손편지 띄우기"(SCR-14), "편지 구독"이 섞여 있다.
- 근거: PM-SCR §2, SCR-06, SCR-14, SCR-15의 표기. 기능 용어를 하나로 쓰기로 한 UX-CTX-ORCH §4.
- 요청: 이름 하나에 화면 하나가 대응하도록 정해 주세요. 예: (A) Header·마이페이지 모두 "편지 구독" → 상태에 따라 편지지 또는 창가로 보냄, (B) 쓰는 곳은 "편지 띄우기"(SCR-14), 보는 곳은 "창가"(SCR-15)로 나눔. 정한 이름은 PM-DOMAIN §3 용어집에도 넣어 주세요.
- 확인 방법: PM-SCR·PM-US 안에서 메뉴·버튼 이름별로 이동하는 화면이 하나씩인지

### R-02 [불편] 우체통 연출이 결제 전에 끝나서, 결제에 실패하면 "넣었는데 안 들어간" 편지가 된다
- 위치: US-11 정상 흐름 2~3, REJ-26, SCR-14 구성("[우체통에 편지 넣기] → 봉투 전환 → 결제"), AC-11-2
- 관련 번호: US-11, AC-11-2, AC-11-6, NFR-10 / G4
- 문제: 봉투가 우체통에 들어가는 연출(1.5~3초)이 끝난 뒤에 결제가 시작된다. 결제를 마치지 못하면 회원은 방금 편지가 우체통에 들어가는 모습을 봤는데 "결제가 완료되지 않았어요"를 보게 된다. 연출이 전하는 "보냈다"는 신호와 실제 상태가 어긋난다.
- 근거: REQ-033(버튼을 누르면 봉투가 닫히며 우체통으로 들어가는 연출), US-11·REJ-26의 순서. 의뢰서는 연출과 결제의 순서를 정하지 않았다.
- 요청: 연출이 실제 상태와 맞도록 순서를 정해 주세요. 예: (A) 결제 확정 뒤에 우체통 연출 재생, (B) 버튼을 누르면 봉투만 닫히고, 결제 확정 뒤 우체통으로 들어감. 어느 쪽이든 REQ-033의 연출 자체는 유지된다.
- 확인 방법: 결제 창을 닫았을 때 우체통 연출이 재생되지 않는지(AC-11-6에 조건 추가)

### R-03 [불편] "편지 도착" 상태에는 화면 문구가 정해져 있지 않다
- 위치: US-12 정상 흐름 2(`arrived` 창문 어두움), AC-12-1, NFR-11
- 관련 번호: US-12, AC-12-1~3, NFR-11 / G4
- 문제: "읽는 중"(AC-12-2)과 "발송됨"(AC-12-3)에는 문구가 있지만 "편지 도착"(AC-12-1)은 어두운 창문뿐이다. 첫 결제 직후에는 "편지가 서점에 도착했어요"가 보이지만(US-11 정상 흐름 4) 다시 들어왔을 때 보이는 문구는 정해져 있지 않다. 어두운 창문만으로는 "아직 아무 일도 없다"와 구분하기 어렵고, 그림을 볼 수 없는 회원에게는 상태가 전달되지 않는다. NFR-11은 표지·실루엣의 대체 텍스트만 정하고 창가 그림(WindowScene)은 다루지 않는다.
- 근거: 운영 정보를 몰라 헛걸음한 경험 [근거: exp-001 §2·§4] (약함), UX-CTX-ORCH §3 "기다림 화면에는 늘 지금 단계 문구", NFR-11
- 요청: AC-12-1에 "편지 도착" 상태 문구(예: US-11의 "편지가 서점에 도착했어요")를 넣고, NFR-11에 창가 그림 3상태의 대체 텍스트 기준을 추가해 주세요.
- 확인 방법: 창가 3상태 모두 화면 문구가 있고, 스크린 리더로 상태를 들을 수 있는지

### R-04 [불편] "책방지기가 요즘 권하는 책"이 실제로는 최근 등록 순 자동 선택이다
- 위치: SCR-01 와이어프레임("책방지기가 요즘 권하는 책"), US-01 정상 흐름 1("책방지기 추천 책"), D-035(재고 있는 책 중 최근 등록 순 4권)
- 관련 번호: US-01, AC-01-1, D-035 / G2
- 문제: 화면 이름은 책방지기가 직접 골랐다고 말하지만, 실제로는 최근에 등록한 책이 자동으로 나온다. 독립서점에서 손님은 운영자의 취향과 목소리를 보고 책을 고른다. 이름과 실제가 다르면 그 신뢰를 해친다.
- 근거: 운영자 개인의 목소리가 서점 경험의 일부였다 [근거: exp-002 §3] (보통), 취향을 발견하는 경험 [근거: exp-001 §2, overview §3-1] (생각, 약함), REQ-012
- 요청: 이름과 실제를 맞춰 주세요. 예: (A) 이름을 "새로 들어온 책"으로 바꿈, (B) 책방지기가 책 관리 화면에서 추천 책을 직접 고름(범위가 늘어나므로 PM 판단).
- 확인 방법: SCR-01 영역 이름과 D-035의 선택 방식이 같은 것을 말하는지

## 동의하는 부분 (바꾸지 않아도 됨)
- SCR-01 "소개 → 테마 → 추천 책" 순서 (UX-CTX-ORCH §3, G1·G2)
- 책방지기 노트 최상단(INV-02, AC-03-1), 해지 흐름에 확인 단계 없음(INV-13, AC-18-2), 택배 정보 미노출(AC-12-4)
- 감성 연출의 시간 기준과 동작 줄이기 대체(NFR-10, D-019, REJ-27, REJ-41)
- 관리자 서재 작업 화면 한 열 순서(NFR-13, G5)
