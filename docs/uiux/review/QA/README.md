# [UI/UX → ⑤ QA] 계획 수립 참고자료 (UX-PLAN-QA)
- 버전: v0.1 / 기반: UX-KNOW v0.1, UX-CTX-ORCH v0.2, PM 문서 7b5d528, `docs/uiux/review/frontend/` v0.1 / 승인: 조성아 (2026-10-21)
- 대상: `qa-agent`가 검증 계획을 세울 때 읽는다. 기능 검증은 PM-AC·NFR이 기준이고, 이 폴더는 그 위에 **사용자 관점 검증**을 더한다.
- `UX-n`의 정의는 `docs/uiux/review/frontend/README.md` §3 한 곳에만 있다. 여기서는 번호로 참조하고 확인 방법만 구체화한다.

## 1. 이 폴더

| 파일 | 내용 |
|---|---|
| `README.md` (이 문서) | 검증 범위, `UX-n` 확인 방법, 시안 대조, 사용자 관점 체크리스트, 브리핑에 적는 법 |
| `scenarios.md` | 페르소나별 핵심 과업 시나리오와 성공 기준 (사용성 테스트·E2E 흐름 테스트 공통) |

## 2. 검증 범위 나누기

| 층 | 기준 | 누가 판정 | 이 폴더에서 |
|---|---|---|---|
| 기능 | AC-xx-n, NFR-xx | QA | — (PM-AC 그대로) |
| 사용성·시각 | UX-1~19 | QA가 확인, 애매하면 UX | §3 |
| 시안 일치 | `screens.md` 시안 | QA가 차이 목록 작성, 판단은 UX | §4 |
| 사용자 과업 | 페르소나 시나리오 | QA가 흐름을 실행, 결과 해석은 UX(작업 D) | `scenarios.md` |

- 사용자 관점 결과는 실제 사용자 테스트가 아니다. 에이전트가 실행한 결과에는 `[AI 시뮬레이션]`을 붙인다(UX 스킬 R6).

## 3. `UX-n` 확인 방법

| 번호 | 자동/수동 | 확인 방법 | 통과 기준 |
|---|---|---|---|
| UX-1 | 자동 | 아래 검색 명령 3개 | 결과 0건 (소셜 로그인 버튼 파일과 일러스트 SVG 컴포넌트는 예외 목록으로 따로 적기) |
| UX-2 | 수동 | 360px 모든 회원 화면 스크린샷 | Header 2줄, 메뉴 4개가 모두 보임, 가로 스크롤 0 |
| UX-3 | 자동 | 각 메뉴 화면에서 `a[aria-current="page"]` 1개 | 현재 화면 메뉴에만 있음 |
| UX-4 | 수동 | SCR-01을 1280×800, 360×640으로 열고 스크롤 없이 스크린샷 | 1280: 제목·소개 글·창가 그림 / 360: 제목·소개 글 첫 줄 |
| UX-5 | 자동 | 화면 렌더 결과(HTML)에서 "할인", "%", "베스트", "순위", "당일", "오늘 출발", "★" 검색 | 0건 |
| UX-6 | 자동 | SCR-03에서 노트 본문의 `getComputedStyle().fontSize`, `fontFamily` | 360: ≥20px, 768+: ≥24px, Gowun Batang, 설명 글보다 큼 |
| UX-7 | 자동 | SCR-03 360px에서 표지 요소 너비 | ≤200px |
| UX-8 | 자동 | 노트·편지·답장·마지막 인사·힌트 요소의 `maxWidth`, `lineHeight` | max-width ≤ 36rem, line-height ≥ 1.8 |
| UX-9 | 수동 | 창가 4상태를 360×640으로 열고 스크롤 없이 스크린샷 | 그림과 상태 문구가 함께 보임 |
| UX-10 | 자동 | SCR-14에 1자, 10자, 2,001자 입력 | 매번 "N / 2,000자"가 바뀌어 보임 |
| UX-11 | 자동 | 화면·상태별 기본 버튼(`data-variant="default"` 또는 기본 버튼 클래스) 개수 | ≤1 |
| UX-12 | 자동 | SCR-16 입력 요소 속성 | input 1개, `inputmode="numeric"`, `autocomplete="one-time-code"`, `maxlength="6"` |
| UX-13 | 수동 | SCR-18 스크린샷을 UX-D-06 줄바꿈과 비교 + AC-18-1 글자 비교 | 줄바꿈 위치 같음, 서명 오른쪽, 버튼 빨간색 아님 |
| UX-14 | 수동 | 데이터 없는 회원으로 SCR-09·12·17, 데이터 조회 실패로 SCR-01 | 정해진 문구 + 다음 행동 1개 |
| UX-15 | 자동 | 빈칸·잘못된 값 제출 후 DOM | `aria-invalid="true"`, `aria-describedby`가 오류 문구 id를 가리킴 |
| UX-16 | 수동 | 화면마다 Tab 키로 끝까지 이동하며 스크린샷 | 모든 초점 요소에 링이 보임, 순서가 화면 위→아래 |
| UX-17 | 수동 | 각 화면 10초 녹화, 동작 줄이기 켜고 다시 | 반복 움직임은 촛불뿐, 동작 줄이기 시 0 |
| UX-18 | 수동 | 관리자 화면 4개 스크린샷 | 상단 바 primary 색, 본문 한 열 |
| UX-19 | 자동 | 렌더 결과에서 `!`와 이모지 범위 검색 | 0건 |

UX-1 검색 명령 (일러스트 폴더 이름은 FE가 정한 경로로 바꾼다):

```bash
rg -n "#[0-9a-fA-F]{3,8}\b|rgb\(|oklch\(" app components --glob '!app/globals.css' --glob '!**/illustrations/**'
```

```bash
rg -n "\[(#|[0-9]+px)" app components
```

```bash
rg -n "style=\{\{" app components
```

- 자동 확인은 Playwright 같은 브라우저 테스트로 짜면 360·768·1280 세 폭에서 같이 돌릴 수 있다. 어떤 도구를 쓸지는 ARCH 품질 게이트(AR-GATE)를 따른다.
- 테스트 이름에 번호를 그대로 쓴다: `UX-12 언박싱 코드는 숫자 키패드 한 칸`.

## 4. 시안 대조

시안: `docs/uiux/review/frontend/mockups/` (화면별 1280·360 PNG). 화면 목록과 상태별 파일명은 `docs/uiux/review/frontend/screens.md`.

| 확인할 것 | 차이가 있으면 |
|---|---|
| 구성 요소의 위→아래 순서, 1단/2단 배치 | `[불편]` 이상 후보로 브리핑에 적기 |
| 버튼 종류(기본/외곽선/글자)와 개수 | UX-11과 함께 판단 |
| 색·글꼴이 토큰과 같은가 (예: 페이지 바탕이 흰색이면 차이) | UX-1과 함께 판단 |
| PM 고정 문구가 글자 그대로인가 | AC 실패로 기록 (PM 기준) |
| 예시 데이터(책 제목, 가격, 편지 내용)와 `[제안]` 문구 | **차이로 적지 않는다** |

- 비교 스크린샷은 시안과 같은 폭(360, 1280)으로 찍고, 전체 페이지(full page)로 찍는다.
- 시안에 없는 768px은 "가로 스크롤 0, 목록 3열(NFR-02)"만 확인한다.

## 5. 사용자 관점 체크리스트

기능 AC와 겹치는 것은 번호만 적었다. QA 계획에 이 묶음을 그대로 넣어도 된다.

**기다림 화면 (P2의 핵심, G4)**
- [ ] 창가 4상태 모두 그림 + 문구 + 같은 대체 텍스트 (AC-12-1~3, AC-12-5, NFR-11, D-043)
- [ ] 결제 창을 닫으면 우체통 들어감 연출이 재생되지 않음 (AC-11-6, D-041)
- [ ] 관리자가 편지를 연 뒤 회원이 다시 들어오면 촛불 (AC-12-6, NFR-17)
- [ ] 어떤 상태에서도 택배사·운송장·단계 숫자 없음 (AC-12-4)
- [ ] 취소 요청 중·거절 문구가 창가에 보임 (AC-12-7, AC-20-6)

**동작 줄이기** (OS 설정 또는 브라우저 `prefers-reduced-motion: reduce` 에뮬레이션)
- [ ] 테마 목록 바뀜, 봉투 닫힘, 우체통 들어감, 언박싱 공개가 모두 0초이고 마지막 모습이 보임 (NFR-10, AC-11-7, AC-16-7)
- [ ] 촛불이 멈춤 (UX-17)

**접근성** (NFR-11 + UX)
- [ ] 키보드만으로 P1·P2·P3 시나리오를 끝낼 수 있음 (NFR-11, UX-16)
- [ ] 스크린 리더로 창가 상태, "장바구니에 담았어요", 틀린 코드 안내가 읽힘
- [ ] 터치 대상 44×44px 이상: 수량 −/+, 테마 알약, Header 링크, [빼기] (NFR-11)
- [ ] 입력 오류가 칸과 연결됨 (UX-15)

**개인정보가 보이는 화면** (NFR-09, INV-19)
- [ ] 다른 회원 계정으로 주문 현황·창가·언박싱·나의 서가 주소를 직접 열어도 내용이 없음
- [ ] 언박싱 전 회차의 응답·HTML 소스에 책 제목·표지 주소·답장·엽서 주소 없음 (NFR-08)
- [ ] 관리자 주문 처리·서재 작업 화면의 주소·연락처가 관리자 외 계정에 보이지 않음 (NFR-06)

**하지 말아야 할 것**
- [ ] 할인·순위·당일 배송 표현 없음 (UX-5)
- [ ] 별점·공유·댓글 없음 (AC-17-3)
- [ ] 해지 흐름에 확인 팝업·혜택 경고·빨간 버튼 없음 (AC-18-2, UX-13)
- [ ] 로그인 화면에 아이디·비밀번호 칸 없음 (AC-05-1)

## 6. 브리핑에 적는 법

- QA 브리핑(`docs/06-qa/briefing-*.md`)에 "사용자 관점 검증" 절을 두고 다음을 적는다.
  - 충족하지 못한 `UX-n` 목록과 스크린샷 경로
  - 시안과 다른 점(§4 기준으로 차이로 적을 것만)
  - 시나리오 결과 표(`scenarios.md` §3 형식) — `[AI 시뮬레이션]` 표시
- 등급은 UX와 같은 이름을 쓴다: `[막힘]` 과업을 끝낼 수 없음·접근성 위반·`UX-n` 미충족 / `[불편]` 헷갈림·일관성 깨짐 / `[취향]`. 등급 판정이 애매하면 `[불편]`으로 적고 UX에 넘긴다.
- UI/UX는 이 브리핑을 읽고 작업 C(검수)·D(사용성 테스트)를 한다. `[막힘]` 수정요청은 사람(조성아) 확인 뒤에 나간다.
