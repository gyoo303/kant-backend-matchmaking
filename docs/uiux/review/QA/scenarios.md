# [UI/UX → ⑤ QA] 페르소나 과업 시나리오 (UX-PLAN-QA / scenarios)
- 버전: v0.1 / 기반: UX-KNOW v0.1, PM-US·PM-AC (7b5d528) / 승인: 조성아 (2026-10-21)
- 쓰는 곳: (1) QA의 E2E 흐름 테스트 묶음, (2) UI/UX의 사용성 테스트(작업 D). 같은 시나리오를 쓰면 두 결과를 비교할 수 있다.
- 에이전트가 페르소나 입장으로 실행한 결과는 `[AI 시뮬레이션]`이며 실제 사용자 테스트를 대신하지 않는다.

## 1. 페르소나

근거 강도 `강함`인 항목은 아직 없다. 나이·직업처럼 과업 판단에 영향이 없는 설정은 넣지 않았다.

### P1. 골목 서가 산책자 (처음 온 방문자)
- 이 사이트에 오는 이유: 책방의 분위기와 책 고르는 방식을 알고 싶다. 독립서점 손님에게는 공간의 분위기와 책이 놓인 방식이 서점의 인상을 만든다. [근거: exp-001 §2·§4, exp-002 §2·§4] (보통)
- 하려는 일: 1) 이 책방이 어떤 곳인지 느낀다 (US-01) 2) 테마로 책을 고른다 (US-02) 3) 책방지기가 왜 권하는지 읽는다 (US-03) 4) 마음에 든 책을 산다 (US-05, 07, 08)
- 불편한 점: 할인·순위만 보이는 쇼핑몰 화면 [근거: REQ-003, overview §3-3] (기초 문서 쪽 약함)
- 사용 환경: 스마트폰 [근거: REQ-016]
- 성공: 첫 화면에서 책방의 결을 느끼고, 노트를 읽고 산 책이 "주문 접수"가 된다.

### P2. 창가의 편지 손님 (편지 구독 회원)
- 이 사이트에 오는 이유: 빠른 배송보다 책방지기와 편지를 주고받으며 책을 기다리는 경험 [근거: REQ-004, REQ-030, REQ-031]
- 하려는 일: 1) 가입 절차 없이 들어온다 (US-05) 2) 편지를 써서 보낸다 (US-11) 3) 창가에서 지금 단계를 확인한다 (US-12) 4) 상자 속 코드로 책을 연다 (US-16) 5) 한 줄 메모를 남긴다 (US-17) 6) 편하게 구독을 마무리한다 (US-18)
- 불편한 점: 아이디·비밀번호와 인증 메일 [근거: REQ-020], 지금 상태를 몰라 헤매는 기다림 [근거: exp-001 §2·§4] (약함)
- 사용 환경: 스마트폰, 밤에는 태블릿·노트북으로 긴 글 [근거: REQ-016]
- 성공: 편지를 보낸 뒤 언제 들어와도 지금 단계를 문구로 알 수 있고, 코드를 넣어 답장을 읽는다.
- 참고: 독립서점과 온라인으로 편지·구독을 주고받은 손님 경험은 기초 문서에 없다(Q-UX-02). 과업은 의뢰서와 PM-US 기준이다.

### P3. 책방지기 (운영자 1명)
- 하려는 일: 1) 책을 등록하고 재고를 바꾼다 (US-06) 2) 도착한 편지를 읽고 책을 골라 답장·힌트와 함께 보낸다 (US-13~15) 3) 주문을 발송·환불하고 주소록을 받는다 (US-10, 19) 4) 취소 요청을 처리한다 (US-20)
- 불편한 점: 기술 지식이 없고, 복잡한 관리자 화면과 화면 오가기가 힘들다 [근거: REQ-005, REQ-050, REQ-051]
- 사용 환경: 의뢰서·기초 문서에 없음 [가정: PC 브라우저]. 360px 확인은 보조로만 한다.
- 성공: 편지 1통을 열기부터 발송까지 다른 화면으로 가지 않고 끝낸다(NFR-13).

## 2. 시나리오

시작 상태(데이터)는 NFR-16 seed를 기준으로 하고, 필요한 상태는 시나리오마다 적었다. "단계 수"는 클릭·입력 묶음 수이며 넘으면 `[불편]` 후보다.

## 3. 결과 기록 형식

QA 브리핑과 UX 사용성 테스트(UX-USAB)가 같은 표를 쓴다.

```markdown
## 사용자 관점 시나리오 결과 [AI 시뮬레이션]
- 대상 버전: <커밋/PR> / 폭: 360, 1280 / 동작 줄이기: 꺼짐·켜짐

| ID | 결과 (성공/어려움/실패/확인하지 못함) | 단계 수 | 막힌 지점 | 관련 UX-n / AC | 스크린샷 |
|---|---|---|---|---|---|
| S1-1 | 성공 | 0 | — | UX-4, UX-5 | docs/06-qa/screens/S1-1-360.png |
```

- 실행할 수 없는 시나리오는 "확인하지 못함"과 이유를 적는다. 추측으로 채우지 않는다.
- "어려움"과 "실패"는 막힌 지점을 페르소나 입장의 한 문장으로 적는다(예: "P2: 어두운 창만 보여서 편지가 도착한 건지 모르겠다").
