## 2. 이 사이트를 쓰는 사람 (요약)

## 4. 계획 세울 때 순서 (권장)

1. **토큰·글꼴 먼저**: `design-system.md` §2·§3 값으로 `app/globals.css`, `app/layout.tsx`를 바꾸는 일은 공통 파일이라 사람이 확인한 토큰 PR로 따로 한다(UX 스킬 §4-4). 이 PR이 없으면 화면 티켓은 기본 shadcn 색으로 보이니, 계획에 선행 작업으로 넣는다.
2. **공통 컴포넌트**: Header, Footer, ProductCard(대체 표지 포함), ThemeSelector, KeeperNote, LetterPaper, WindowScene, BlindBook, 관리자 레이아웃 (design-system §5 표).
3. **화면**: 맡은 SCR의 `screens.md` 절과 시안 → PM-AC → 구현 → 같은 폭(360·1280)으로 찍어 시안과 비교한 스크린샷을 브리핑에 넣는다.

## 5. 시안 다시 만들기

시안을 고쳐야 하면 UX가 고친다. ④는 시안 파일을 고치지 않는다.

```bash
node docs/uiux/review/frontend/mockups/src/build.mjs
```

```bash
node docs/uiux/review/frontend/mockups/src/shoot.mjs
```

- `build.mjs`가 `mockups/html/`을, `shoot.mjs`가 Chrome(또는 Edge) headless로 `mockups/*.png`를 만든다. 글꼴은 Google Fonts에서 받아 오므로 인터넷 연결이 필요하다.
- `mockups/src/mockup.css`는 시안 전용이며 제품 코드가 아니다. 값의 기준은 `design-system.md`다.

## 6. UI/UX에게 물어볼 때

- 명세·시안에 없는 화면 상태가 필요하거나, 요청이 `UX-D`의 `금지`와 부딪치면 브리핑 "사람이 결정할 것"에 적고 멈춘다.
- 시안과 PM-SCR이 다르면 PM-SCR를 따르고 브리핑 "명세와 다르게 한 것"에 적는다.
- 작업 중 사람이 내린 디자인 판단은 브리핑 "기록 필요"에 적는다. UX가 `decisions.md`로 옮긴다.
- 아직 답이 없는 질문(이 답에 따라 시안이 바뀔 수 있음): Q-UX-06 메인 방문 안내, Q-UX-07 내지 이미지, Q-UX-08 행사·모임, Q-UX-09 책방 공간 사진 (`docs/uiux/domain/open-questions.md`).
